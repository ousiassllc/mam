- **進捗は HTMX のポーリング**: 動いているジョブのある区画（エンジンのカード・モデルの一覧）は `hx-get` と `hx-trigger="every 2s"` を持ち、ジョブがなくなると属性が消えて止まる。取り直しの URL はジョブの ID を持ち（`?job=`・`?jobs=`）、ジョブが終わった取り直しで、結果（導入した／失敗の理由）を 1 度出す。WebSocket は使わない。
- **操作の応答は、変えた区画だけ**（`hx-target="#mm-…"`・`outerHTML`）。導入の完了・エンジンの削除は、ほかの区画（モデルの一覧）を `hx-swap-oob` で描き直す。
- **破壊的な操作**（エンジンの削除・モデルの削除・導入の中断・トークンの削除）は `hx-confirm` を持つ。送信ボタンは `hx-disabled-elt` と `hx-sync="this:drop"` で二重送信を防ぐ（`double_submit_test`・`destructive_confirm_test` が検査する）。
- **使うモデルの選択**（Issue #1015）: 複数のモデルを持つ実行環境（Irodori-TTS）のカードの詳細モーダルに、`organisms/modelmgr/runtimecard.RuntimeModels`（ラジオ。`data-testid=mm-runtime-models`・`mm-runtime-model`）を出す。モデルごとに、名前・説明・取得量・言語・VRAM の目安（mam の推定と、この PC の GPU との比較）・ライセンスと商用の答え・使うときの制限（`mm-runtime-model-cautions`）、同意が要るモデルはライセンスのテキストとチェックボックス（`accept_<モデル>`。値はテキストの版。同意済みなら「同意済みです」）。「このモデルにする」で `PUT /model-manager/runtimes/:id/model`（[endpoints-model-manager.md](../api/endpoints-model-manager.md)）。同意のチェックが無い・版が違うと 409 で何も変えない。意味は [local-runtime.md §14.5・§14.6](../architecture/model-manager/local-runtime.md)。モデル一覧の絞り込み（#1011）の項目は、統合のときに合わせる。
- **モデルのフィルター**（Issue #1015・#1011）: 「使うモデルの選択」の上に、モデルマネージャーの一覧と同じフィルターバー（`molecules/modelpick`。検索・漏斗・チップ・件数）を置く。`GET /model-manager/runtimes/:id/models` が `#mm-runtime-model-list-<id>` を差し替える。パネルには、その実行環境のモデルを見分ける欄だけを出す（VRAM・商用は常に、種類・言語は実行環境のモデルの間で違うときだけ、非検閲は 1 つでも持つとき）。一覧を描き直しても、押していたラジオと同意のチェックは残る。詳細は [local-runtime.md §14.8](../architecture/model-manager/local-runtime.md)。
- **ローカル音声・口パクの区画**（Issue #920）: ルートと挙動は [endpoints-model-manager.md](../api/endpoints-model-manager.md) §3。①カードは設定の `settingsui` と同じ面（`rounded-lg border border-border bg-surface p-4`）で、状態は文字のバッジ（色だけで伝えない）。②**商用利用のバッジ**は 3 値（可 = `BadgeOK`、不可 = `BadgeError`、**はっきりしない** = `BadgeWarn`。文言は「商用利用: 可」「商用利用: 不可」「商用利用: はっきりしません」）で、`data-commercial` にも値を持つ。③`unclear` / `no` の重みは、その行に琥珀色の枠（`role="note"`）で `notice`、重みの一覧の前に件数と名前を挙げる枠（`mm-runtime-unclear`）を出し、`<details>` を**開いた状態**で描く（閉じたままにしない）。④使えない環境の理由とクラウドの案内は `role="note"` の枠で、導入ボタンは出さない。⑤重みの導入・起動・導入は `hx-sync="this:drop"` と `hx-disabled-elt`、削除と導入の中断は `hx-confirm`。⑥出典・ライセンスのリンクは `rel="noopener noreferrer"`・`target="_blank"`（取得元は `https` だけ）。⑦新しい色は足さない。
- **入力の長さ**は定数（`MaxTokenLen`・`MaxAspectLen`、プロンプトは `gentest.MaxPromptRunes`）で、テンプレートに数字を書かない（`maxlength_test`）。

## カードと詳細モーダル（#954）

モデルを並べる所は、**1 つのカード部品 `molecules/modelcard`（`Item`・`Actions`）** だけを使う。声（GPT-SoVITS）・口パク（MuseTalk 1.5）・画像モデル・動画モデルも、Hugging Face から追加したファイルも、外部の ComfyUI のモデルも、同じ形で並ぶ。

- **カードに出すもの**（これだけ）: ①絵（アイコンのタイル。下記）、②名前（`<h3>`）、③名前の下の 1 行（種類・用途と大きさ。ランタイムは用途と必要な空き容量）、④商用利用のアイコン（`commercial.Mark`。語はツールチップとアクセシブルネーム。`data-commercial` はフィルターの鍵として `<li>` に残る）、⑤状態のバッジ（未導入／導入中／導入済み／ファイルが不足。ランタイムは起動の状態・「この PC では使えません」など）、⑥見落としてはならないバッジ（成人向け・HF トークンが必要・導入先の空きが足りません・VRAM が足りない見込み／VRAM に余裕なし・更新あり）、⑦導入中の進捗バーとメッセージ、導入・削除・中断・起動・停止などのボタン、直前の操作の結果とエラー。説明文・ライセンス・ファイル・SHA-256・VRAM の数値・原本の場所・トリガー語は、カードに出さない。
- **絵は新しく取ってこない**: モデルの画像（サムネイル）はネットから取らず、同梱もしない（出どころとライセンスの管理が要るため）。代わりに、**種類ごとの Iconoir のアイコンのタイル**（`atoms`。MIT。`icons/LICENSE`）を絵にする: 画像モデル = `IconImage`、動画モデル = `IconVideo`、声 = `IconVoice`（audio-lines）、口パク = `IconLipSync`（scan-face）、追加したファイル = `IconPackage`、外部の ComfyUI のモデル = `IconNetwork`。タイルは装飾（`aria-hidden`）で、意味は隣の文字が持つ。カタログに画像のフィールドは無い。モデルごとの画像が要るときは、その出どころとライセンスをカタログに持たせる別の決定が要る。
- **見た目と色**: 面は `rounded-lg border border-border bg-surface p-4`、一覧は `grid gap-4`（列数は節「カードの列数（#1102）」。それまでは、モデルの一覧・追加したファイル・外部の ComfyUI のモデルは 1 列・2 列〔640 px〜〕・3 列〔1024 px〜〕、ランタイム・追加ノードは 1 列・2 列〔1024 px〜〕だった）。**開くカード**の枠は `pick.OpenFrame`: ホバーで選ぶカード（#906）と同じ枠（`indigo-400`）と光る縁取り、キーボードのフォーカスは名前のボタンが持つとき `` の輪。選ぶのではないので面（`bg-accent-soft`）は塗らない。色は [color-rules.md](color-rules.md) のトークンだけで、新しい生の色は足さない。
- **開く操作**: 名前は `<h3>` の中の `<button data-card-open aria-haspopup="dialog">` で、`after:absolute after:inset-0` でカード全体がタップの面になる。ボタンは `modal.OpenAttrs(詳細の URL, フォーカスキー)` で、`GET` の答え（`modal.Frame`）をページに 1 つの `<dialog id="mam-modal">` の本体へ入れる（設定のモーダルと同じ仕組み。第 2 の仕組みは作らない）。カードの操作ボタンは `modelcard.Actions`（`relative z-10 mt-auto`）に入れ、タップの面より上にして、押すとボタンが動く（モーダルは開かない）。商用利用のアイコンも `z-10`。
- **詳細モーダル**（ルートは [endpoints-model-manager.md](../api/endpoints-model-manager.md)）: ①`GET /model-manager/models/:id/detail`（`modeldetail.Detail`: 説明・種類・状態・商用利用のバッジと注意（`commercial.Note`）・地域の制限・トークンの案内・大きさ・VRAM の目安と判定・ライセンスのリンク・商用利用・トリガー語・原本の場所・必要な空き容量・**ファイルごとの大きさと SHA-256**・共有しているモデル・導入されるモデル）、②`GET /model-manager/runtimes/:id/detail`（`runtimecard.RuntimeDetail`: 説明・使えない理由とクラウドの案内・導入済みの版・待ち受け・必要な空き容量・VRAM・GPU・導入先・ソースとライセンス・**重み・依存ファイルごとの出典・ライセンス・商用利用・ファイルと SHA-256**・`unclear` の注記）、③`GET /model-manager/hf/models/detail?path=`（`modeldetail.HFDetail`: リポジトリとコミット・ライセンス・SHA-256・作ったモデル）、④`GET /model-manager/external/detail?endpoint=&name=`（`modeldetail.ExternalDetail`: あるファイルと足りないファイル）。SHA-256 は `<code data-testid="mm-sha256">` で、カタログの値と同じ（テストが全モデル・全ファイルで突き合わせる）。見つからない・隠しているモデル（年齢確認前の成人向け）は、理由だけのモーダル（`modal.Notice`。404 / 409）で、隠しているモデルの名前や中身は出さない。
- **キーボード・スクリーンリーダー**: `<dialog>` は `showModal()` で開くので、Esc で閉じ、フォーカスは中に閉じ込められ、後ろは inert になる。`Host` は `aria-modal="true"` と、見出し（`#mam-modal-title`）への `aria-labelledby`、説明（`#mam-modal-desc`）への `aria-describedby` を持つ。開いたとき、フォーカスは詳細の先頭のブロック（`tabindex="-1" autofocus`。`modal.StartClass`）に入り、長いモーダルが下の「閉じる」の位置で始まらない。閉じると、`data-focus-key`（`open-<カードの id>`）で、**カードが描き直されていても、新しいカードの同じボタン**にフォーカスが戻る（`modal.ts` の `restoreFocus`。カードの `<li>` には安定した `id` がある）。
- **ポーリングとモーダルは干渉しない**: モーダルは `Body` の中の区画（描き直される要素）の**外**（区画の後ろ）に 1 つだけある。導入中のカード・一覧（`hx-trigger="every 2s"`）が `outerHTML` で入れ替わっても、開いているモーダル・その中のフォーカス・ページのスクロール位置は動かない。応答にモーダルは含まれない（テストが保証）。カード自体も `hx-get`（ポーリング）を持つランタイムは、`<li>` の属性に持つ。**#908 の「導入ボタンで一番下までスクロールされる」件の直し方は、この節に含まれない**（`inline-dialog` と同意ダイアログの扱いは変えていない）。
- **説明文は「?」ヘルプに**: 区画の見出しの横の「?」（#866）に、カードをタップすると詳細が見られること、実行環境が mam とは別のプログラムで SHA-256 を確かめてから使うこと、自動起動・アンインストールの意味、空き不足・VRAM 不足の表示、成人向けモデルの案内を入れた。区画の本体には、カード・状態・エラーだけが残る（成人向けの設定のカードは「成人向けモデルは表示していません。」の 1 行）。ライセンスの同意のダイアログ（`ConsentDialog`）・年齢確認のダイアログ（`AdultDialog`）は今までどおり、ページの中の区画（`#mm-dialog`）。
- **文字数**（可視テキスト。1280×800 で、実ブラウザの `innerText`。「?」の中身は閉じているので数えない。実カタログ 12 モデル・GPT-SoVITS 導入中・MuseTalk 未導入）: ローカル音声・口パクの区画 11,887 → 127 字、モデルの一覧（`#mm-catalog`）5,728 → 572 字、モデルマネージャー全体 18,602 → 1,636 字。


## 更新ボタンとエンジンのカード（#962・#970）

- **更新ボタン**（Issue #962。#925 の `RefreshBar` を `molecules/refresh.Bar` に移して、単発生成の履歴と共用）: 更新アイコンだけの小さなボタン（`aria-label`・`title` は「更新」。要求中はアイコンが回る。`id` は `<対象の id>-refresh` で固定、取り直しのあとも htmx がフォーカスを戻す）と、あれば `最終更新 15:04:05`。押すと、対象の区画（`outerHTML`）だけを、その区画の GET で取り直す。`hx-sync="#<対象>:replace"` で、出ている自動更新の要求を置き換える。人が押した要求なので、`poll-guard`（タブが隠れている・動画が再生中のときの自動更新を止める。`static/src/components/poll/poll-guard.ts`）は止めない。

  - カードの `<ul role="list" class="…GridClass…" data-testid="mm-ollama-models">`（列数は #1102 の `modelcard.GridClass`）。1 枚は `<li id="mm-ollama-<名前の `:`・`.` を `-` にしたもの>" data-testid="mm-ollama-model" data-model="gemma4:12b" data-state="…">`（`modelcard.Item`）: アイコン（`IconPackage`）・名前（`<h3>`。画面の名前「Gemma 4 12B（純正）」）・名前の下の 1 行「Ollama: gemma4:12b・約 8.0 GB」・商用利用のアイコン（`commercial.Mark`。カタログの答え）・状態のバッジ（未取得 `missing`／取得中 `pulling`／取得済み `installed`／**上流で更新されています** `changed`／使えません `unavailable`。色だけで伝えない）・取得中の進捗バーと段階の文（「manifest を取得しています」「データを取得しています（42%・3.2 / 8.0 GB）」「検証しています」。`role="status"`）・ボタン（取得／中断する／削除。`aria-label` は「<操作>: <画面の名前>」）・直前の結果とエラー。空き不足は「導入先の空きが足りません」のバッジ（他のモデルのカードと同じ）。

  - **そのほかのモデル**: 管理している Ollama が持つモデルのうちカタログに無いもの（利用者が自分で取得したもの）を、一覧の末尾の別の見出し「そのほかのモデル」（`data-testid="mm-ollama-others"`）に名前とサイズだけで並べる（取得・削除のボタンは出さない。削除は利用者の `ollama rm`）。Ollama が止まっている間は出さない（取得のボタンを押さずに起動しない）。
  - 取得は管理している Ollama が未導入なら押せない（ボタンを `disabled`＋理由）。止まっているときは押せる（取得のジョブが起動する）。`hx-sync="this:drop"`・`hx-disabled-elt`・削除と中断は `hx-confirm`。
- **ポーリング**: 取得中のカードがあるとき、`#mm-ollama` が `hx-get="/model-manager/ollama?jobs=<job>,…"`・`hx-trigger="every 2s"` を持つ（なくなると止まる）。終わった取り直しで結果（「取得しました」／失敗の理由）を 1 度出す。更新ボタン（`molecules/refresh.Bar`。`id` は `mm-ollama-refresh`）。取得の完了・削除は、同じページの `#mm-llm-use-state`（取得済みのモデル数が変わるとき。状態の行だけ）を `hx-swap-oob` で描き直す。ほかのページの区画は描き直さない。
- **LLM の割り当てとの関係**: `use` が `ollama` の間、設定の LLM のモデル選択に、取得済みのモデルがすべて出る（local-runtime.md §19.3）。使われている割り当てのモデルは、削除が 422（使っている Agent の名前を出す）。取得を始めても割り当てを自動では変えない。
- **a11y**: 状態は文字。進捗は `role="status"`。ボタンの名前に画面の名前。未導入・停止中の理由は `aria-describedby` で取得のボタンに結ぶ。
- **テストで見ること**: `GET /model-manager/local-llm` に `#mm-ollama` がちょうど 1 つ。カタログの 3 つのカードが `data-model` と一致し、`modelcard.GridClass`。未導入で取得のボタンが `disabled`・理由の行が出る。偽の Ollama（NDJSON の `/api/pull`）で、進捗が合計に対する割合になり、層が切り替わっても戻らない・`success` のあと `verified`／`changed`・`error` の行で失敗の理由・中断・空き不足の 409。削除（使用中の 422・取得中の 409・未取得の 409）。そのほかのモデルの表示。`cloud` を含む名前・`library` 以外の名前を、どのルートに送っても 422（実行されない）。CSRF のトークンが無い要求は 403。`mm-ollama-noauth` が詳細に出る。macOS・AMD の理由と案内。

### 決定が要ること

- **自由入力の `ollama pull`**（既定: しない。厳選した 3 つのカードだけ。自由入力は、①ライセンスと成人向けの扱いを mam が確かめられない〔レジストリに HF のようなタグの API が無い〕②`cloud` タグ〔プロンプトを外へ送る〕を避ける必要がある。入れるなら: 名前の欄＋同意のチェック〔「mam はこのモデルのライセンスと内容を確認していません」。HF の導入と同じ形〕・`library` の名前だけ・`cloud` を拒否・商用は `unknown`・年齢確認が済むまで出さない）。
- **取得の方式**（既定: Ollama 自身の `/api/pull`。層の digest の検証は Ollama が行い、mam は取得後に manifest を照合して `verified`／`changed` を出すだけ。別案: mam がレジストリの blob を `fetch`〔Range 再開・SHA-256 固定〕で取得して `OLLAMA_MODELS` に書く。mam の固定は強くなるが、Ollama の内部形式〔blob と manifest の置き場所〕に依存し、Ollama の更新で壊れうる）。
- **`changed` のときの扱い**（既定: 使えるまま・注記だけ。別案: 使用を止める〔タグが正規に更新された場合も使えなくなる〕、または取得後の内容を固定のカタログの digest と合わなければ消す）。
- **認証が無いことの扱い**（既定: 注意書きだけ〔local-runtime.md §19.4〕。別案: mam が認証つきのループバックのプロキシを前に置く〔新しいプロセスと仕組みが要る〕）。
- **AMD の GPU・macOS・Windows arm64**（既定: 対応しない。理由と案内を出す。AMD は `ollama-windows-amd64-rocm.zip` を重ねる形で足せるが、実機で確かめられない）。
- **厳選する名前**（既定: `gemma4:12b`・`qwen3.8:27b`・`deepseek-r1:14b`。llama.cpp の純正モデルと同じ系統。非検閲の派生は載せない）。

## 手元の LoRA の取り込み（#1119）

区画 `#mm-lora`「LoRA を追加」は `image-video` ページの「モデルの一覧」の下に置く（`mmcat` の `Sections` に `mm-lora`）。部品は `organisms/modelmgr/loraimport`（`Section`・`PanelView`・`ListView`・`ListOOB`）。意味と検査は [model-manager-lora.md](../architecture/model-manager/model-manager-lora.md)、ルートは [endpoints-model-manager.md](../api/endpoints-model-manager.md)。

- **見出しの横の「?」**: 見出しは `molecules.SettingsSection("LoRA を追加", loraimport.Help)`。説明（ベースモデルとの対応・強さ・トリガー語・ライセンス）は「?」の中に置き、画面に長い文を並べない。
- **選ぶ**（`data-testid="mm-lora-pick"`）: ファイルの選択（`accept=".safetensors"`）と、ドロップの領域（`mm-lora-zone`）。ドロップしたファイルも同じ入力に入れて送る。ブラウザ側で拡張子と大きさ（4 GiB）を先に確かめ、通らないものは送らずに理由を出す（`mm-lora-client-error`）。送っている間は進捗（`mm-lora-progress`。割合とバイト）を出し、`htmx:xhr:progress` で更新する。
- **確認**（`mm-lora-staged`）: ファイルの情報（大きさ・SHA-256）、名前（使えない文字を置き換えたときは理由）、ベースモデルの選択（ファイルから読めたときは「ファイルの情報から読み取りました」、無いときは「未設定」）、推奨の強さ、トリガー語（学習で多く使われたタグは候補として別に出し、欄には入れない）、ライセンスの名前と商用利用の答え（不明・条件つき（自己申告）・商用NG。「商用OK」の選択肢は無い）。「追加する」（`mm-lora-commit`）と「取り消す」（`mm-lora-discard`）。同名があるときは確認の上に案内の箱（`mm-lora-conflict`）を出し、別の名前の提案を欄に入れる。
- **結果**: 追加できたら確認の文（`mm-lora-notice`。単発生成の「LoRA と強さ」で選べること）、拒否は入力欄の上（`mm-lora-msg`）に理由を出す。入力は消えない。上の検査に通らないファイルは、置かずに理由だけを出す（`mm-lora-error`）。
- **追加した LoRA の一覧**（`#mm-lora-list`）: 1 つが 1 枚のカード。名前・大きさ・ベースモデル・強さ・トリガー語・ライセンス（空は「不明」）。編集のフォームと削除のボタン。空のときは「まだ追加していません。」（`mm-lora-empty`）。
- **この PC で使えないとき**（バンドルのエンジンが動かない環境）は、区画に理由（`mm-lora-unsupported`）だけを出し、選ぶフォームを出さない。
- **単発生成・レシピ側**: `molecules/loraselect`（`Select`・`Note`）が「LoRA と強さ」の選択と注意を描く。注意（`data-testid="gt-lora-note"`）は、選んだ LoRA の未設定の項目、ワークフローのベースモデル（`data-lora-family`）との食い違い、`commercial_only` のときの商用の注意を出す。`static/src/components/gentest-lora` が、モデルの切り替え・LoRA の選び直しで注意を更新する。止めはしない。
