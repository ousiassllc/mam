# 非機能要件

`spec/overview.md` のスコープ（ローカル起動型 Web アプリ、シングルユーザー前提。Windows 版は Wails ウィンドウで同じサーバーを開く）に基づく非機能要件。

## 1. 実行環境 / 互換性

| 項目 | 要件 |
|------|------|
| OS | Windows 10 以降 / macOS 12 以降 / Ubuntu 22.04 以降（Go バイナリの対応OS） |
| ブラウザ | 各ブラウザ（Chrome/Edge/Firefox/Safari）の安定版最新2バージョンをサポート対象とする。HALT の HTMX + Lit（ES2022, Custom Elements v1。Lit コンポーネントは Shadow DOM を使わず Light DOM に描画する）が動作すること。Windows の Wails ウィンドウ版は WebView2（Evergreen。Chromium 系で Edge と同じエンジン）で表示し、同じ要件を満たすこと |
| アーキテクチャ | x64 / arm64。`make build-all`（`scripts/build.sh --all`）が Windows・macOS・Linux × x64・arm64 の 6 構成のブラウザ版を `bin/mam-<os>-<arch>[.exe]` に生成する（単一バイナリは `make build`）。Windows では ONNX Runtime のバインディングが対応しないため顔同一性の定量評価（Face Identity Similarity）は使えず、AI Video Judge は定性評価にフォールバックする |
| 配布 | GitHub Releases に Windows x64 の成果物 2 つだけを載せる: ① NSIS インストーラー exe（`mam-<version>-windows-amd64-setup.exe`）、② Wails ウィンドウ版のポータブル `mam.exe`（`mam-<version>-windows-amd64.exe`）。`v*` タグの push で GitHub Actions（`.github/workflows/release.yml`）が自動で作る。コード署名はしない（SmartScreen の警告が出る。README に手順を書く）。macOS・Linux・Windows arm64 の成果物は載せない。インストーラーは WebView2 ブートストラッパーを含み、WebView2 が無い Windows 10 では取得して入れる（インターネット接続が必要。ポータブル版は含まないため、WebView2 が無い環境ではインストーラー版を使う）。ffmpeg は同梱せず（実行時に任意）、README とインストーラー完了画面で PATH への導入を案内する。アンインストールではデータディレクトリ（既定: `%AppData%\mam`）を削除しない |
| ネットワーク | 外部生成モデル API 呼び出しにはインターネット接続が必須。ブラウザ／Wails ウィンドウ（WebView） ↔ バックエンド通信はローカルループバック（127.0.0.1）のみで完結し、オフラインでも UI 操作・既存プロジェクト閲覧は可能。例外はインストール時の WebView2 ブートストラッパーの取得のみ |

## 2. 性能

| 項目 | 要件 |
|------|------|
| UI 応答性 | HTMX フラグメント swap のループバック往復（サーバー処理時間）は 100ms 以内を目標（DB問い合わせのみのアクション） |
| 生成ジョブの非同期性 | 画像/動画生成・Judge・Repair はすべてバックグラウンドジョブとして実行し、UI スレッド（HTTPリクエスト処理）をブロックしない |
| 進捗通知 | 生成中の Take/Shot の進捗は WebSocket 経由でリアルタイムに UI へ反映する（ポーリング禁止） |
| プレビュー再生 | 1080p 動画のプレビュー再生はコマ落ちなく再生できること。4K アセットはサムネイル/プロキシ生成で代替表示を許容する。プロキシを作れなかったとき（ffmpeg が無い・失敗・上限時間切れ）は原本で代替し（コマ落ちしうる）、失敗は 10 分間覚えて再試行しない。変換はクライアントの切断では止めず、同じファイルにつき 1 回だけ走る |
| 起動時間 | プロジェクトを開いた際の Chat Workspace（`GET /projects/:id`）の初期表示は 3 秒以内（ローカル SQLite 読み込みのみの場合） |

## 3. 可用性 / 復旧性

| 項目 | 要件 |
|------|------|
| SLA | 単一ユーザー・ローカル実行のためサーバー稼働率 SLA は定義しない |
| クラッシュ復旧 | アプリ異常終了後の再起動時、実行中だった生成ジョブのステータスを検出し、未完了ジョブを再開または安全に失敗として扱う（中途半端な Take/State を残さない） |
| オートセーブ | Shot/Take/World State の変更は都度 SQLite にコミットする（明示的な保存操作を必須としない） |
| 外部プロセスのハング | ffmpeg / ffprobe は上限時間付きで実行し、超えたら強制終了して失敗（`media.ErrTimeout`）にする。ハングしたプロセスがジョブワーカー・プレビューのロック・リクエストを握り続けないための安全策。上限は固定値で設定画面からは変えられない: プローブ 30 秒、ラウドネス測定 10 分、エンコード・デコードは 2 分 + 5 秒 × 素材の秒数（長い素材ほど長く待つ）。強制終了後も出力パイプは 5 秒で閉じる。呼び出し側のキャンセルは上限超過とは区別する（`ctx.Err()`）。生成ジョブでは `generation.FailureReason` が「動画・音声の処理（ffmpeg）が制限時間を超えました」と利用者へ通知する |
| サーバーの時間制約 | HTTP サーバー（`app/http.go` の `runHTTP`）の時間は固定値で設定画面からは変えられない: リクエストヘッダーの読み取り 10 秒、アップロード以外のリクエスト本文の読み取り 5 分、Keep-Alive の待機 2 分。書き込み（応答）には上限を付けない（動画などのメディアは配信に何分かかっても時間では切らない）。アップロード（`readMultipart` を呼ぶルート。`POST /projects/import` の 8 GB など）は全体の所要時間に上限が無く、読み取りが 1 分間止まったとき（無通信）だけ打ち切る。遅い回線・ディスクでも、データが流れ続ける限り 8 GB のバンドルを取り込める。打ち切られると読み取りエラーで、途中で切断されたときと同じ 400「送信内容の形式が正しくありません」（`spec/api/endpoints.md` §0） |
| データ整合性 | SQLite は WAL モードで運用し、Orchestrator からの書き込みはシングルライター（内部キューでシリアライズ）とする。生成物ファイル（動画/画像）の書き込みは一時ファイル→リネームによるアトミック書き込みとする |

## 4. スケーラビリティ

| 項目 | 要件 |
|------|------|
| プロジェクト規模 | 1プロジェクトあたり Scene/Shot/Take 数百件、Take あたり複数バージョンのファイル資産を保持していても、一覧表示の初期表示が 2 秒以内、検索結果表示が 1 秒以内で返ること（一覧・チャット履歴はページングせず全件を 1 回の問い合わせで取得して描画し、画像・動画のサムネイルだけを `loading="lazy"` で遅延読み込みする。ローカルの SQLite では、job を持つ進捗カード 1,000 件のチャット履歴の取得・整形が約 16 ms、Project 一覧が 1 ms 未満であり、この規模では全件描画で目標を満たす。N+1 クエリを避けるため、履歴の整形は job・返信先・添付を一括取得する） |
| ディスク容量 | 生成前に空き容量を見積もり、不足時は警告してから生成を開始する。見積もりは Take 1 秒あたり 2 MiB（約 16 Mbit/s の概算）× Take 数 × Shot の長さで、空きがそれ未満なら Shot ごとにチャットへ警告する（実際の動画がこれより大きい・小さいときは警告に誤差が出る）。不要 Take のアーカイブ/削除機能を提供する。Take のプロキシ・サムネイルと Rough Cut のプレビューは `assets/.previews` に必要になった時点で作るキャッシュで、Take のアーカイブで当該 Take の分を削除し、合計が 4 GiB を超えたら最後に使われた（再生・要求された）のが古いものから削除する（LRU。作ってから古いものではない）。Storage 画面に合計サイズを表示する。強制終了で残った変換の一時ファイル（`assets/.previews/.<名前>.ffmpeg.tmp`）は起動時に削除する |
| 同時実行 | 同一プロジェクト内で複数 Shot の並列生成（Prompt Candidate Generation の Quality Mode 等）を許容する。外部モデル API のレート制限に応じて同時実行数を Model Adapter 側で制御する |
| マルチプロジェクト | 複数プロジェクトの並行オープンはサポートしない（M1〜M2）。将来的な複数プロジェクト同時操作は本要件の対象外とする |

## 5. セキュリティ

| 項目 | 要件 |
|------|------|
| ローカルサーバー公開範囲 | Go バックエンド（Gin/Huma）は `127.0.0.1` のみにバインドし、外部ネットワークからアクセス不可とする |
| API キー管理 | 外部生成モデル API のキーは OS のセキュアストレージ（Windows Credential Manager / macOS Keychain / Linux Secret Service）に保存し、平文設定ファイルに書かない |
| CSRF | ループバック限定であっても HALT 標準の CSRF トークン付与（meta タグ + 全リクエストへの付与）は維持する |
| コンテンツセキュリティ | 全応答に `Content-Security-Policy`（スクリプトは自前の `/static/app.js` のみ、フレーム埋め込み禁止）と `X-Content-Type-Options: nosniff` を付け、htmx・Lit が「他のスクリプトを実行しない」前提をブラウザ側でも強制する（詳細は `architecture/overview.md` §6） |
| 入力検証 | ユーザーアップロード画像/参照動画は、サービス層（`service/upload.go`）で拡張子・ファイル内容の署名（先頭バイト。MIME は拡張子から決める）・サイズ・件数を検証し、違反は 422 で拒否する。上限は画像 20 MB・動画 300 MB・一度の添付 8 件。アップロードは Gin の multipart ハンドラ（`POST /projects/:id/references` など）で受け、Huma（`/api/v1`）の Input バリデーションは通らない。サーバーの `ReadTimeout`（5 分）は絶対期限で 8 GiB のバンドルが遅い回線・ディスクで収まらないため、アップロードの本文は 1 回の読み取りごとに 1 分のアイドル期限へ延ばす（受信が続く限り打ち切らない） |
| Brand/Safety 制約 | Safety and Brand Constraints（禁止表現・権利メタデータ等）は Prompt 生成・AI Video Judge・Final QC の全段階で強制適用し、LOCK 違反はスコアに関係なく FAIL とする（F-23 と対応） |
| テレメトリ | デフォルトで外部への利用状況送信は行わない。診断ログはローカルファイルにのみ出力する |
| チーム共有物の漏えい防止 | 他のメンバーに渡すもの（Review Package・Review Response、F-32）には、外部モデル API キー・認証情報、顔データ（Character / Series の顔基準画像・参照画像・アップロード素材・顔同一性指標）、Brief・チャット・Notes・World State・Prompt・Brand Constraints・コスト・Project ID・絶対パスを含めない。渡すのは allowlist の項目（Project 名・オーナーのメモ・レビュー対象の Final Export 1 本、レビュアーの表示名・判定・コメント）だけで、固定の構造体から組み立てる。読み込み側は allowlist 外のエントリ・サイズ超過・署名不一致を拒否する（`spec/spec.md` §27.1） |
| チーム利用の認証 | アカウント・ログイン・サーバーを持たない。レビュアーは自己申告の表示名で識別し、検証しない。ファイルの受け渡し経路の秘匿は利用者が担う。ローカルサーバーの `127.0.0.1` 限定と CSRF は変えない |

## 6. コスト制御

| 項目 | 要件 |
|------|------|
| 予算上限 | Project budget ceiling / Shot budget ceiling をユーザー設定可能とし、超過が見込まれる生成はブロックまたは警告する |
| リトライ制御 | Max retries per Shot / Max cost per Shot / Minimum acceptance score を Repair/Retake Loop に適用し、無限再生成を防止する |
| モデル呼び出し耐性 | 外部 API の 429（レート制限）・5xx・ネットワーク断に対し指数バックオフで再試行し（LLM はタイムアウトも再試行する。課金を伴う画像・動画生成ではタイムアウトを再試行せず、二重課金を避けて代替モデルへフェイルオーバーする）、プロバイダ単位でサーキットブレーカーを設ける。M3 の Multi-model routing（`architecture/model-adapters.md` §13）は使うモデルの順序（プライマリ/代替）だけを決め、OPEN のベンダーのモデルを先頭に選ばない。再試行・フェイルオーバー・同時実行数の制御は変えない |
| コスト可視化 | Shot/Scene/Project 単位の推定コストと実コストを UI に表示する |

## 7. 可観測性 / トレーサビリティ

| 項目 | 要件 |
|------|------|
| 生成トレース | 各 Take について Source Shot Spec / World State version / Prompt version / Model / Model parameters / Model routing（選択理由、M3） / References / Output / Judge result / Repair history を保存する（F-27） |
| ログ | Go バックエンドは構造化ログ（レベル別）をローカルファイルにローテーション出力する |
| バージョン復元 | Shot / Take / Branch / World State の主要変更を Version 化し、以前の状態へ復元できる（F-28）。復元は指定バージョンの内容を新バージョンとして追記する（履歴を消さない）。LOCK 中の項目を変える復元は行わない |
| 制作指標（Production Analytics） | MVP Success Metrics（`spec/spec.md` §28）はローカルの SQLite（Take / Judge Result / Repair Action / Cost Ledger / Export / Edit Timeline / `human_intervention`）だけから集計し、外部へ送信しない（§5）。人間の介入・上書きの記録も同じ DB に追記する。`GET /projects/:id/analytics`・`GET /analytics` で表示する |

## 8. データポータビリティ

| 項目 | 要件 |
|------|------|
| エクスポート/インポート | プロジェクト全体（Project Data Model + アセット参照）をポータブルなバンドル（アーカイブファイル）としてエクスポート/インポートできる。クラウド同期基盤は前提としない。バンドルは ZIP（`manifest.json`・`data.json`・`assets/`）で、インポートは同じ ID の Project が無い環境へ ID とファイルパスを保ったまま復元する。取り込める Project ID と全テーブルの行 ID は `[A-Za-z0-9_-]{1,64}`（UUID を含む）に限り、サーバーが `assets/` 直下で使う `reviews`（Review Package の動画置き場 `assets/reviews/`）と Windows の予約デバイス名（`CON`・`PRN`・`AUX`・`NUL`・`COM1`〜`COM9`・`LPT1`〜`LPT9`）は、大文字小文字を区別せず使えない（Windows・macOS の既定のファイルシステムは大文字小文字を区別せず、`Reviews` が `reviews` と同じディレクトリになるため）。ファイルパス（`file_path`・Audio Timeline が指すパス）は `<project_id>/` の下で、Project ディレクトリの外へ出ず、`\`・`:`・NUL・`..` を含まず、`/` で区切った各要素が Windows で作れる名前であること（`CON`・`PRN`・`AUX`・`NUL`・`COM1`〜`COM9`・`LPT1`〜`LPT9`・上付き数字の `COM¹`〜`COM³`・`LPT¹`〜`LPT³` は拡張子付き〔`NUL.mp4`〕も含め大文字小文字を区別せず、`*`・`?`・`"`・`<`・`>`・`|`・制御文字を含まず、末尾が `.` や空白でない。末尾の `.`・空白は Windows が落とすため `a.` と `a` が同じファイルになる。取り込む全ファイルのパスの間でも、大文字小文字だけが違う 2 本（`x.mp4` と `X.mp4`）と、ファイルとディレクトリが同名になる 2 本（`x` と `x/y.mp4`）は取り込めない（`bundlepath.Conflict`。Windows・macOS では後に書いた方が先の方を黙って上書きする）。`bundlepath.ValidFilePath`）。中断したインポートの展開先（`assets/.import-*`）は起動時に削除する |
| チーム共有（レビュー） | プロジェクトバンドルは自分の端末間の移行・バックアップ用で、顔基準画像などを含むため他人に渡すものではない。チームでの共有は、動画 1 本とメモだけの Review Package（F-32、`spec/spec.md` §27.1）で行い、クラウド同期基盤は前提としない |
| 最終成果物書き出し | Final Export は指定 Aspect Ratio / 解像度 / コーデックで動画ファイルをローカルへ書き出す |
