## 1. 今の画面との関係

| 段 | 何をする所 | 実体 |
|---|---|---|
| **かんたん**（初期表示） | やりたいことを選ぶ → モデルとおすすめの設定が決まる。品質 3 ボタン・サイズ 3 ボタン・プロンプトと入力画像だけ | 新しい。`organisms/gentesttier`（`easy.templ`） |
| **こだわり** | 今の生成テスト画面の作成フォームそのもの（モデルのカード・複数のプロンプトとネガティブ・本数・縦横比・**詳細設定（#973）**・入力画像・LoRA）。かんたんで選んだ値が最初から入り、変えた項目に印が付き、「元に戻す」ができる | 今のフォーム（`organisms/gentest`・`gentestadv`）＋ `gentesttier/refine.templ` と `static/src/components/gentest-tiers/refine.ts` |
| **ComfyUI** | ノードで作る段。**今ある機能への入口だけ**を出す（ノード画面 `/nodes`・保存したワークフロー `/workflows`・モデルの設定 `/settings/local-models`・モデルマネージャー）。偽の UI や「準備中」は出さない。第 2 段（今の設定をグラフで開く・画面に出す値）はここに足される | `gentesttier/tabs.templ` の `ComfyPanel` |

- 段の切り替えは、フォームの上のタブ（`nav[aria-label="作り方"]`。ページ間のタブ `generationNav` と同じ流儀: 今の段は `aria-current="page"` の `span`、他は `a`）。かんたん ⇄ こだわりは、フォームを**入力したまま**差し替える（HTMX。入力済みの値を `hx-include` で送り返し、`hx-push-url` でアドレスも変える）。スクリプトが無くても、ただのリンク（`?tier=`）で開ける（入力は持ち越さない）。ComfyUI は別の画面への入口なので、入力を持ち越さない普通のリンク。
- **動画のフォームには段が無い**（今のまま）。画像／動画の切り替えは、今までどおり `GET /generation-test/form`。
- プロジェクトの画像・履歴・ポーズ集から選ぶ入力画像、見積り → 確認 → 実行、進捗と比較表、履歴は、3 段とも同じもの（かんたんも `ConfirmBox`・`BatchBox` を使い、見積りを必ず先に出す）。

### 段の決め方（URL）

- `GET /generation-test?tier=easy|detail|comfy`。無い・知らない値は**かんたん**。`tier` はフォームの hidden（`input[name=tier]`）にもあり、見積りは `tier=easy` のときだけ、やりたいことからモデルを決める。確認の hidden はモデルを持つので、`tier` は持たない。
- モデルを**名指す**入口（`?model=`・`?from_result=`（プロンプトマッチの回）・`?again=`）は、`tier` を付けなければ**こだわり**で開く（かんたんはモデルを自分で選ぶ段なので、名指されたモデルが選ばれないため）。`?prompt=`（プロンプト履歴）と `?ref=`（結果の「入力画像として使う」）はモデルを名指さないので、**かんたん**で開く（プロンプト・入力画像が入った状態。入力画像があるので、画像を使えるモデルが選ばれる）。動画のモデルを名指したときは動画のフォームで、段は無い。
- `?again=<結果の id>`（＋`same_seed=1`）は §5 の復元。`?ref=…&ref_role=face&intent=face&tier=easy` は「この顔で作る」。

## 2. かんたん

- **やりたいこと**: 人物写真・アニメ・風景・同じ顔で（`input[type=radio][name=intent]`。選択肢のカードは `molecules/pick`）。選ぶと、その下の「使うモデル」と品質のボタンだけを `GET /generation-test/easy-pick` で差し替える（ブラウザで選んだ入力ファイルを壊さない）。
- **選択肢と各モデルの対応はデータ**（`backend/internal/service/gentest/intent/intents.json`。バイナリに埋め込む。理由は §7）。各選択肢は、モデルの**候補を好みの順に**持つ（カタログのワークフロー名。`flux1-dev` なら ID は `comfyui:bundled-comfyui/flux1-dev`）。選ぶのは、候補のうち次のすべてを満たす最初のもの（`gentest.Service.Recommend`）:
  1. **導入済み**で、今呼べる（`modelcatalog.Info.Available`。導入されていない・同梱エンジンが無いモデルは候補にならない）。
  2. 成人ゲート（`Hidden` = `modelmanager.HidesModel`）が閉じているあいだは、成人向けのモデルは**一覧に無い**ので選ばれない。
  3. 設定「商用OKのモデルだけを使う」のフィルター（`modellicense.DefaultFilter`）に合う（フィルターの意味は [../architecture/model-license.md](../architecture/model-license.md) §5）。
  4. この PC の OS・GPU が、モデルのカタログの列（`requires`・`unsupported`。#979）の外でない（警告があるものは選ばない。`Deps.PlatformWarning`）。
  5. 入力画像があるときは入力画像を使えるモデル（`reference_only` の img2img ワークフローは、入力画像があるときだけ候補になる）。「同じ顔で」は顔の役割（`face`）を読めるモデル。
- 候補に専用でないもの（アニメ向けが無いときの汎用モデル）が入っているときは、`note`（「アニメ専用のモデルが使えないため、汎用のモデルで作ります。…」）を**選ばれたモデル名の下**に出す。入力画像があるのに画像を使えないモデルしか無いときは、画像を使わない旨を添える。
- 選ばれたモデル名は小さく出す（`data-testid="gt-easy-model"`。「使うモデル: …」）。選ばれたモデルの `<li data-model>` のカード（見えない。こだわりのカードと同じ作りで `input[name=model]` を持つ）が、入力画像・詳細設定のスクリプトにモデルの性質を渡す。
- **該当モデルが 1 つも無いとき**: 理由（`data-testid="gt-easy-nomodel"`）と、モデルマネージャーへのリンク「モデルマネージャーを開く」。理由は、導入されていない（「「人物写真」に合うモデルが、まだ導入されていません。モデルマネージャーで導入してください」）か、導入済みだが条件に合わない（商用フィルター・OS・GPU・顔を読めない）かを言い分ける。見積りのボタンは押せない（`disabled`）。
- **品質**: 「速い／標準／きれい」の 3 ボタン（`input[type=radio][name=quality]`。`fast`・`standard`・`high`。既定は標準）。§3 のプリセットを使う。**プリセットを持たないモデルでは 3 ボタンを出さず、理由を出す**（`data-testid="gt-quality-reason"`）: ステップ数・CFG を受け取らない（クラウドのモデルなど）／速さのモードが決める（#973 の決定。Speed mode のあるモデルは steps・cfg を上書きできない）／プリセットが無い（4 ステップで作る蒸留モデルなど）。
- **サイズ**: 「縦／横／正方形」（`input[type=radio][name=aspect_ratio]`。`9:16`・`16:9`・`1:1` = こだわりの縦横比の入力と同じフィールドと同じ値）。こだわりで別の比（`4:3` など）にしてかんたんに戻っても、サイズは変わらない（その比が 4 つ目のボタンとして残る）。
- **入力**: プロンプト（`textarea[name=prompt]`）と入力画像（今の入力画像の区画をそのまま使う。ドロップゾーン・サムネイル・役割と強さ）だけ。ネガティブ・本数・英訳の設定は、フォームの hidden として**持ち越す**（かんたんで触れないだけ。こだわりで入れたものは、かんたんに戻っても消えない）。複数のプロンプトがあるとき、2 つ目以降も hidden で持ち越す。
- **何も触らずに生成すると、今と同じ品質のグラフ**（標準＝今のテンプレートの既定値）: 品質が標準（または無い）のとき、リクエストは steps・cfg を**何も上書きしない**（`Request.Quality` が空 = 上書きなし）。テンプレートのグラフが今までどおりに走る（`service/gentest/qualitytest` がグラフを比べて保証する）。
- 「**詳細設定を開く**」は、こだわりへ移る（`SwitchAttrs(detail)`）。かんたんで選んだ値は §4 のとおり持ち越す。
- 見積りは、かんたんでも**先に出す**。見積りの応答は、やりたいことからモデルを決めて見積もる（`tierform.Resolve` → `Service.ApplyIntent`）ので、確認の hidden には決まったモデル（`model`）が入り、「この内容で実行する」は見積りと同じリクエストを走らせる（モデルが途中で変わらない）。

## 3. 品質のプリセット（モデルごとの値）

- プリセットは**テンプレートのワークフローに持たせる**（`backend/internal/agent/modeladapter/localcfg/templates/image/*.json` の `workflow.quality_presets`）。理由は §7。形は `{"fast": {"steps": N, "cfg": C}, "high": {"steps": N, "cfg": C}}`（各項目は省ける。`steps`・`cfg` は #973 の `Param` が載る値）。**標準は書かない**: 標準 = そのワークフローのグラフが持つ値そのもの（上書きなし）。
- 値は mam の目安（モデルカード・テンプレートの既定から、速い = 既定より少ないステップ・きれい = 既定より多いステップに寄せたもの）で、**GPU では確かめていない**（`needs_real_device`）。`quality_presets` を持つテンプレート: SDXL 系（`txt2img-sdxl`・`-clipskip2`・`-controlnet`・`-ipadapter`・`img2img-sdxl`・`-clipskip2`: 速い 15・きれい 40。標準 25）、FLUX.1 dev（`txt2img-flux-dev`・`-lora`: 12・30。標準 20）、Chroma（16・40。標準 26）、Qwen-Image・Qwen-Image-Edit-2511（12・30。標準 20）、Qwen-Image 2.1（15・40。標準 25）、SD3.5 Medium（18・40。標準 28）。FLUX.1 schnell・FLUX.2 klein は 4 ステップで作る蒸留モデルなので**持たない**（3 ボタンの代わりに理由が出る）。インペイント・アップスケールのテンプレートも持たない。
- 読み込みの検査（`localcfg.ValidateModel`）: プリセットは、そのワークフローが受け取る値（steps・cfg の割り当て）にだけ書ける。速さのモードを持つワークフローは持てない。範囲は #973 と同じ。速いはワークフローの steps より少なく、きれいは多くなければならない（ボタンが言うとおりに動くため）。
- 効き方: リクエストの `quality`（`fast`／`high`）は、**リクエストが steps・cfg を名指ししていない項目だけ**にプリセットの値を入れる（`sampling.Caps.WithQuality`）。名指した値（こだわりのスライダー・MCP の `sampling`）が勝つ。受け取らないモデル・速さのモードのモデル・プリセットの無いモデルに `quality` を送ると、見積りの警告 `quality_ignored`（標準の値で作る）。標準を送るのは空と同じ。
- 結果に残るのは、実際に使った steps・cfg（`params.sampling`。#973）なので、品質の名前を別に残す必要は無い（結果の「使った設定」から作り直せる）。
- すでに導入済みのモデル（プリセットが入る前に作られたコピー）は、起動時の `wfrefresh` が、**テンプレートの steps から変えていないコピーだけ**プリセットを持つテンプレートへ更新する（利用者が steps などを編集していれば触らない）。

## 4. こだわり（詳細設定）

- 中身は今の作成フォーム（モデルのカード・プロンプトとネガティブ・パラメーター・**詳細設定（#973）**・入力画像・LoRA・参照画像の強さ）。**無い入力を新設しない**: ネガティブ・LoRA と強さ・参照画像の強さは、これまでの場所にあり、こだわりの上の「変えた項目」の欄が一箇所に集めて見せる。
- **かんたんで選んだ値が最初から入っている**: かんたん → こだわりのとき、選んだモデルがそのままカードで選ばれ、品質のステップ数・CFG が詳細設定のスライダー（「上書きする」が入った状態）に入る。入れた旨の 1 行（`data-testid="gt-carried"`。「かんたんで選んだ「速い」（モデル・ステップ数 15）を入れました。変えた項目には印が付き、元に戻せます」）が出る。標準のときは何も入れない（上書きしない = 標準）。入力済みの値（プロンプト・縦横比・入力画像・LoRA）は、段を替えても残る。
- **こだわりからかんたんに戻る**と、かんたんで選んだやりたいこと・品質が見つかる（`easy_intent`・`easy_quality`。リクエストは読まない。読むと、こだわりのスライダーの値を上書きしてしまうため）。
- **変えた項目に印**: 段が始まったときの値（かんたんで入れた値）と今の値が違う項目に「● 変えた」の印（`data-gt-mark`、`data-gt-changed`）が付く。対象: シード・ステップ数・CFG・サンプラー・スケジューラー・ネガティブ（プロンプトごと）・LoRA と強さ・参照画像の強さ（入力画像ごと。役割に追従する既定は、利用者が動かすまで「変えた」に数えない #960）。印は色だけにしない（文字つき）。
- **元に戻す**: 項目ごと（「◯◯を元に戻す」の小さなボタン）と全体（「全部を元に戻す」）。戻る先は、**段が始まったときの値**（かんたんで入れた値。無ければモデルの既定）。変えた項目の一覧（`data-testid="gt-refine-list"`、`aria-live="polite"`）が「ステップ数: 30（元は 15）」のように言う。変えた項目が無いときは「変えた項目はまだありません」と出す。規則は `refine-model.ts`（vitest）、DOM は `refine.ts`（web-test-runner）。
- 「プロンプトの語を選ぶと +/− が出る」と「レシピとして保存」は**第 2 段**（ここには無い）。

## 5. 結果の画面

結果の詳細（`ResultDetail`）の、画像の下に（`organisms/gentestresult`）:

- **ボタン列**（`data-testid="gt-next"`。画像の結果でファイルがあるときだけ）: 「一部だけ描き直す」（#974。今の `inpaintlink.Links` を使う。描き直した結果には「元の結果」へのリンク）・「大きくする」（#975。下の `#gt-upscale` の箱へのリンク。箱が出ない結果には出さない）・「似た感じでもう1枚」・「この顔で作る」・「この設定でもう一度」。動画・失敗・取り消しの結果には出さない。
- **似た感じでもう1枚**＝同じ設定・シードだけ変える（`GET /generation-test?tier=detail&again=<id>`）、**この設定でもう一度**＝同じ設定・同じシード（`…&same_seed=1`）。どちらも**こだわりで開く**（再現に必要な値がすべて見える）。記録された `params` から入力を復元する: モデル・プロンプトとネガティブ・英訳の有無・縦横比・steps・cfg・サンプラー・スケジューラー・LoRA と強さ・「ポーズを真似させない」・入力画像（履歴・プロジェクト・ポーズ集の画像と、その役割・強さ）。「同じシード」は、モデルがシードを渡せたときだけ入る。**復元できない項目は理由を出す**（フォームの上の 1 行）: アップロードした入力画像（残っていない。入れ直す）・元の履歴の画像やプロジェクトの画像が消えている・モデルが今は使えない・シードを受け取らないモデル。インペイント・アップスケールの結果には出さない（元の画像とマスクはフォームの入力ではない）。
- **この顔で作る**: 結果の画像を、役割 `face`（#960）の入力画像として入れ、かんたんの「同じ顔で」を開く（`?tier=easy&intent=face&ref=history::<id>&ref_role=face`）。顔の役割を読めるモデルが選ばれる。
- **使った設定**パネル（`details[data-testid=gt-used]`。**折りたたみ**）: モデル・ステップ数・CFG・サンプラー・スケジューラー（`params.sampling`。モデルが受け取らないときは「受け取りません」の 1 行）・シード・LoRA（名前と強さ）・サイズ（縦／横／正方形つき）。今の詳細の表（`gt-params`）は残す（こちらは全項目）。

## 6. a11y・色

- タブとボタンは今のタブ・ボタン部品（`generationNav` と同じクラス・フォーカスの輪）。選択肢のカードは `molecules/pick`（見えない本物のラジオ。Tab・矢印キー・読み上げがそのまま使える）。色は [color-rules.md](color-rules.md) の許可リストだけ。補助の文字は `text-neutral-400` 以上。
- 「変えた」は色だけにせず文字を付ける。変えた項目の一覧は `aria-live="polite"`。

## 7. 判断した点

- **URL はクエリ（`?tier=`）**: 段は同じ画面（`/generation-test`）の状態で、パスを分けると、戻る・入力の持ち越し・既存の入口（`?model=` など）が複雑になる。ブラウザの戻る・リロードで同じ段に戻れるよう、段を替えるとアドレスも変える（`hx-push-url`）。
- **プリセットはテンプレート（ワークフロー）に持たせる**: モデルの性質（steps の既定・蒸留かどうか・どの値が速さに効くか）は、そのグラフと一緒に決まり、テンプレートを足すとき（`localcfg/templates/**`）に同じ場所で直せる。モデルのカタログ（`modelmgr/catalog/data/models`）は「何をダウンロードするか」のデータで、複数のワークフローが同じモデルを別の steps で使い（SDXL の txt2img と img2img など）、導入済みのモデルが持つのは**ワークフロー**なので、カタログに置くとグラフの値と二重管理になる。`Caps`（`list_generation_models` の `sampling`）に載るので、画面と MCP は同じものを読む。
- **選択肢と対応するモデルのデータは `service/gentest/intent/intents.json`（埋め込み）**: 「やりたいこと → 候補モデル」は**生成テスト（画面と MCP）の選び方**であって、モデルの導入データ（`modelmgr/catalog`）でも、モデルのワークフロー（`localcfg`）でもない。カタログの流儀（埋め込み JSON を `DisallowUnknownFields` で読む）に合わせ、選択肢や候補の追加は JSON の編集だけで済む。候補はカタログのワークフロー名で書き、テスト（`TestTheIntentsNameWorkflowsOfTheCatalog`）が、実在しない名前を許さない。
- **`quality` は `Request` の 1 項目**（画面の hidden・MCP の引数・見積りの検証が同じ形）。リクエストが steps・cfg を名指ししていればそちらが勝つ（こだわりの値が勝つ）。
