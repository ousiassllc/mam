# モデルマネージャー: 手元の LoRA を「ファイルを追加」で取り込む

[model-manager.md](model-manager.md) の続き（`model-manager.md` が長いため別ファイル。HF からの導入は [model-manager-hf.md](model-manager-hf.md)）。Civitai などで**利用者が自分でダウンロードした LoRA（`.safetensors`）を、画面から選んで、同梱の ComfyUI の `loras` フォルダに取り込む**。状態: 実装済み（Issue #1119）。

これは**この PC の中への取り込み**（ローカルのコピー）で、ネット上への公開・アップロードではない。Civitai との連携・ログイン・ダウンロードの自動化は範囲外。取り込みと生成は別で、**取り込んだだけでは生成は始まらない**（ジョブも作らない）。

実装: 検査 `backend/internal/modelmgr/lorafile`・取り込み `backend/internal/service/modelmanager/loraimport`（`Service.LoRAs`）・画面 `web/handler/modelmgr/loraimport`＋`web/organisms/modelmgr/loraimport`・単発生成の選択 `web/molecules/loraselect`＋`static/src/components/gentest-lora`・MCP `mcp/tools/modelmgr/loratools`。

## 1. 流れ（2 段）

利用者がファイルの中身を見てから置けるように、2 段にする。

1. **確認（`Stage`）**: ブラウザが選んだ（またはドロップした）ファイルを、`<comfyui>/imports/<乱数>.part` へ**ストリームで**書く（一時ファイルを経由する二重のコピーをしない。書きながら SHA-256 を計算する）。書き終えたら §2 の検査をかける。通れば、ファイルの情報（大きさ・SHA-256・ファイルの `__metadata__` が書くもの・同名のファイルがあるか）を画面に返し、利用者の確認を待つ。通らなければ理由つきで拒否し、`.part` を消す。`loras` フォルダには何も置かない。
2. **追加（`Commit`）**: 利用者が確認した値（保存するファイル名・対応するベースモデル・推奨の強さ・トリガー語・ライセンス）を受け取り、同名のファイルが無いことを確かめて、`imports/` のファイルを `data/models/loras/<名前>` へ **`rename` 1 回**で移す（`imports/` は `data/` と同じ `comfyui` の下で、同じボリューム。途中まで書かれたファイルが `loras` に現れない）。`state.json` の `local_loras` に記録する（§5）。記録に失敗したらファイルを戻す。

- 確認待ちのファイルは**同時に 3 つまで**、**1 時間**で捨てる。mam の起動時に `imports/` を空にする。「取り消す」で捨てる。拒否した追加（同名など）は確認待ちのまま残し、名前を直してやり直せる。
- **同梱エンジンが無い環境**（`engine.Supported` が偽。Linux・Intel Mac など）では取り込まない（`loras` の置き場が無い）。外部の ComfyUI を使うときは、その `loras` フォルダに直接置く。エンジンが導入済みである必要は無い（置くだけ。選べるのは、エンジンが起動していて `LoraLoaderModelOnly` の `lora_name` に出るとき）。
- 画面だけでなく **MCP からも使える**（§7）。1 回で済ませる版（`Import` = `Stage` + `Commit`。同名なら拒否して何も残さない）を使う。

## 2. 検査（`lorafile`）。すべて Service の側で強制する

| 検査 | 内容 |
|---|---|
| ファイル名 | 空・`/`・`\`・`..`・制御文字を含むものは拒否（パスの踏み越え）。拡張子は **`.safetensors` だけ**（大文字小文字は問わず小文字にそろえる）。`.ckpt`・`.pt` などの pickle 形式は、読み込むときにプログラムが動く恐れがあるため拒否（理由を書く）。使える文字は英数字と `. _ + -`（それ以外は `_` に置き換え、「名前を変えた」と画面に出す）。Windows の予約名・120 文字超も `hfplan.ValidName` と同じ規則で直す。ブラウザが送った名前は、ディレクトリを落とす前の生の値を見る（`../../x` を `x` に黙って直さない） |
| 大きさ | 1 バイト以上 **4 GiB まで**（実際の LoRA は数十 MB〜2 GB。それ以上はチェックポイントなどの大きなモデル）。リクエストの宣言と、実際に受け取ったバイト数の**両方**で見る（宣言が小さくても上限で打ち切る）。空き容量が足りなければ書く前に拒否 |
| ヘッダー | 先頭 8 バイトの長さが 1 以上・`MaxHeaderBytes`（8 MiB）以下で、ファイルの大きさに収まること。JSON のオブジェクトで始まること。各テンソルが `dtype`・`shape`・`data_offsets` を持ち、データの範囲が**ファイルの中に収まり、隙間も余りもなくデータ全体を覆う**こと（safetensors の仕様。途中で切れたダウンロードもここで見つかる） |
| LoRA か | テンソル名を、HF の導入がフォルダを決めるのと**同じ表**（`hfplan.Infer`）にかけ、`loras` と判定されたものだけ通す（`lora_unet_*`・`lora_te*`・`*.lora_A/B.*`・`*.lora_down/up.*`・`*.alpha`）。チェックポイント・VAE・テキストエンコーダー・拡散モデルのファイルは「LoRA ではなく、○○のファイルのようです」と理由つきで拒否する |

## 3. 同名のファイル（上書きしない）

- `loras` フォルダの中に、**大文字小文字を区別せず**同じ名前があれば競合（Windows・macOS は区別しないため）。競合は上書きせず、(a) 確認の段で画面に出す（既存のファイル名・同じ内容かどうか・空いている別名の案）、(b) 追加の段でも拒否する（`*InvalidError`。別名の案を添える）。
- 別名の案は `<名前>-<SHA-256 の先頭 8 桁>.safetensors`（HF の導入と同じ `hfplan.SuggestName`）。それも使われていれば連番を足す。画面は名前の欄に案を入れ、利用者が直して追加できる（明示の確認）。
- 競合の相手は、記録のある LoRA でも、利用者が手でフォルダに置いたファイルでも、カタログのモデルのファイルでも同じ（**どれも上書きしない**）。**同じ内容**（大きさ・SHA-256 が同じ）の場合は「すでに〇〇としてある。追加は要らない」と言い、追加ボタンを出さない。
- 追加と削除は、導入と同じ宛先のロック（`lockDests`）の下で行う。同名の導入ジョブ（HF）と取り合っても、後の方が先の結果を見て拒否される。HF の導入は、記録のある LoRA のパスを「別のファイルがある」として扱う（`recordedAt` が `local_loras` も読む）。

## 4. ファイルが言うことと、利用者が確認したこと

`__metadata__`（sd-scripts・modelspec の鍵）から読む値は、**フォームの初期値**にするだけで、記録するのは**利用者が確認した値**。ファイルに無い値は空で、画面は「未設定」と書く。**推測で確定しない**。

| 項目 | 読む鍵 | 読めないとき |
|---|---|---|
| 対応するベースモデル（複数可） | `modelspec.architecture`・`ss_base_model_version` を `lorafamily.FromMetadata` が系統（`sdxl`・`sd1`・`sd3`・`flux`・`chroma`・`qwen-image`・`wan`）に写す。写せない値（FLUX.2 など知らないもの）は系統にせず、**書かれたままの文字を「ファイルに書かれたベースモデル」として見せる**だけ | 未設定（どれも選ばない） |
| トリガー語 | `modelspec.trigger_phrase`・`trigger_words`・`trigger_word`（カンマ・改行区切り）。`ss_tag_frequency`（学習で多く使ったタグ）は**候補として上位 10 件を表示するだけ**で、トリガー語の欄には入れない（トリガー語かどうか分からないため） | 空欄（未設定） |
| 推奨の強さ | ファイルからは**読まない**（鍵が標準化されていない） | 空欄（未設定）。利用者が 0.05〜1 で入れる |
| ライセンスの名前 | `modelspec.license` を欄の初期値にするだけ。**商用利用の答えはファイルから決めない** | 空欄（不明） |
| そのほか表示 | `modelspec.title`・`ss_network_dim`・`ss_network_alpha` | 出さない |

- ファイルの中身は信用しない。文字列は制御文字を除き 120 文字で切り、トリガー語は 1 語 80 文字・30 語まで。`ss_tag_frequency` は 1 MiB までしか読まない。
- 利用者は追加の後も「情報を編集」で、ベースモデル・強さ・トリガー語・ライセンスを書き換えられる（ファイルには触れない）。

### 4.1 ライセンスと `commercial_only`

- 入力は任意。**未入力は「不明」**（商用利用の答え `unknown`）。**勝手に商用OKにしない**: 利用者が選べる答えは「不明」「条件つき（配布元で商用可と確認した、利用者の自己申告）」「商用NG」で、`yes`（商用OK）は**選べない**（HF の `FromHF` と同じく、自己申告だけでは商用OKにしない。`modellicense.FromUser`）。
- 設定「商用OKのモデルだけを使う」（`commercial_only`、[model-license.md](../model-license.md) §5）との整合: この設定は**一覧を絞るだけで、生成そのものは止めない**。LoRA の選択（単発生成の「LoRA と強さ」）は、設定がオンのとき、商用OKと確認できていない LoRA を選ぶと**警告を出す**（選択肢からは外さない。手でフォルダに置いた LoRA はもともと答えが無く、外すと使えなくなるため。生成は止めない）。LoRA の答えはモデルの答え（`commercial`）に合成しない（LoRA は別のファイルとして選ぶ）。

## 5. 記録（`state.json` の `local_loras`、鍵 `models/loras/<名前>`）

`path`・`name`・`original_name`（選んだファイル名）・`sha256`・`size`・`base_models[]`（`lorafamily` の鍵）・`strength`（無ければ省略）・`trigger_words[]`・`license_name`・`commercial`（`""` = 不明 / `conditional` / `no`）・`added_at`。値の検査（`Meta.check`）: ベースモデルは系統の鍵だけ、強さは 0 より大きく 1 以下（単発生成の LoRA の強さの範囲）、トリガー語は §4 の上限、ライセンス名は 1 行 120 文字まで、`commercial` は上の 3 値だけ。

- **削除**（`Delete`）は、**記録のある LoRA だけ**（ファイルと記録を消す）。記録の無いファイル（手で置いたもの・カタログのモデルのもの）は触らず `ErrNotFound`。
- `List`（新しい順）は `present`（ファイルが実在し大きさが合う）を付ける。ファイルが消えていても記録は残り、画面は「ファイルが見つかりません」と出す。
- 既存の「Hugging Face から導入」の記録（`user_models`）とは別の表。HF の導入・削除・一覧は変えない。

## 6. 追加した LoRA を使う（単発生成・レシピ）

- 追加した LoRA は、エンジンが起動していれば `LoraLoaderModelOnly` の `lora_name` に出るので、単発生成の「LoRA と強さ」（`#gt-lora-name`。**レシピはこのフォームの値を保存する**ので同じ）の選択肢に並ぶ。選択肢の文言は、mam が追加した LoRA だけ「（商用利用の答え）」を付ける（「条件つき」「不明」など）。
- **選択肢の `data-*` と、選んだ LoRA の下の注記**（`static/src/components/gentest-lora`）: mam が追加した LoRA は `data-known=true` と対応するベースモデル・推奨の強さ・トリガー語・答えを持つ。注記は「対応するベースモデル」「推奨の強さ」「トリガー語（プロンプトに入れてください）」「商用利用」を出し、**未設定は「未設定」「不明」**と書く。mam が追加していないファイル（手で置いたもの）は「未設定」の 1 行だけ。
- **ベースモデルとの整合（警告）**: LoRA を受けるワークフローは `workflow.lora_family`（`lorafamily` の鍵。ベースのチェックポイントの系統）を持てる（Qwen-Image・FLUX.1 dev・Chroma の LoRA つきテンプレートに付けた）。選んだ LoRA の対応するベースモデルに、チェックされているモデルの系統が**含まれない**とき（両方が分かっていて違うとき）、「○○は △△ 用のモデルです。この LoRA は □□ 用のため、合わない組み合わせです（効かない・画が崩れることがあります）」と**警告する**（止めない）。LoRA のベースモデルが未設定、またはモデルが系統を言わないときは、合う・合わないを判断せず、前者は「未設定のため、選んだモデルに合うか確かめられません」と添える。モデルを選び直す・LoRA を選び直すたびに注記が更新される。
- **推奨の強さ**: 記録に強さがあれば、LoRA を選んだとき強さのスライダーをその値にする（利用者がスライダーを動かした後は動かさない）。無ければフォームの既定のまま。

## 7. MCP（画面と同じ Service。判断: **画面と MCP の両方で使える**）

- 理由: MCP にはファイルを渡す経路がある（`create_upload_ticket` が URL を返し、その URL へ multipart で 1 回送る。[mcp-tools.md](../../api/mcp-tools.md)）ので、「ファイルを渡せないから画面だけ」にはならない。#830 の方針（画面の全操作を MCP で操作できるようにする）に従い、画面の操作を対応づける。大きさの上限は画面と同じ 4 GiB（チケットの上限として `max_bytes`）。**ホストのパスを引数に取る形にはしない**（エージェントが PC 上の任意のファイルを読めてしまうため）。
- アップロードの用途 `model_lora_import`（確認の段が無いので 1 回で追加する）、ツール `list_user_loras`・`update_user_lora`・`delete_user_lora`。入力の値と拒否は画面と同じ（同名は上書きせず `validation`、別の `name` を付けてやり直す）。**ファイルの `__metadata__` が書くベースモデルとトリガー語は、`adopt_metadata=true` を渡したときだけ記録する**（渡さなければ、与えた値だけ。強さとライセンスはどちらの場合もファイルから取らない）。商用の答えに `yes` は渡せない。
- 単発生成の `list_generation_models` の `loras`（エンジンが持つ LoRA のファイル名）には、追加した LoRA がそのまま出る（`lora.name` に使う）。

## 8. 未検証・範囲外

- 実機の ComfyUI で追加した LoRA を使った生成は**していない**（有料・GPU の生成はしない決まり）。確かめたのは、ファイルが `loras` に置かれ、`LoraLoaderModelOnly` の選択肢（偽のエンジン）に出て、選択肢の `data-*`・注記が出ること。
- 範囲外: Civitai との直接連携・ログイン・ダウンロードの自動化・ネット上への公開。ControlNet・アップスケーラーなど `loras` 以外のフォルダへの取り込み。
- `lora_family` を付けたのは LoRA を受ける 6 つの画像テンプレート（Chroma・FLUX.1 dev + LoRA・Qwen-Image Edit 2511・Qwen-Image 2.1・同 GGUF・同 VNCCS）。付けていないテンプレート（保存済みの手書きのワークフローなど）は系統を言わない（警告しない）。

## 9. テスト

`lorafile`（検査の表・ファイル名・メタ情報の読み取り）・`service/modelmanager/loraimport`（取り込み・拒否・上限・転送の途中切れ・同名・期限・値の検査・ライセンスの既定・更新と削除・1 回の取り込み）・`web/handler/modelmgr/loraimport`（入口・端から端まで・メタ情報あり／なしの表示・拒否・同名・同じ内容・取り消し・編集と削除・ジョブを作らないこと）・`web/handler/gentest/reftest`（選択肢の `data-*`・モデルカードの系統）・`mcp/tools/modelmgr/loratools`（アップロード・拒否・更新と削除）・`static/src/components/lora-import`・`gentest-lora`（vitest と wtr: 事前の検査・ドロップ・進捗・注記・警告・推奨の強さ）。
