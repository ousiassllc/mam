## 1. 今の画面との関係

| 段 | 何をする所 | 実体 |

| **こだわり** | 今の生成テスト画面の作成フォームそのもの（モデルのカード・複数のプロンプトとネガティブ・本数・縦横比・**詳細設定（#973）**・入力画像・LoRA）。かんたんで選んだ値が最初から入り、変えた項目に印が付き、「元に戻す」ができる | 今のフォーム（`organisms/gentest`・`gentestadv`）＋ `gentesttier/refine.templ` と `static/src/components/gentest-tiers/refine.ts` |
| **ComfyUI** | ノードで作る段。**今ある機能への入口**（ノード画面 `/nodes`・保存したワークフロー `/workflows`・モデルの設定 `/settings/local-models`・モデルマネージャー）と、今の設定をグラフで開く入口・画面に出す値（§10）を出す。偽の UI や「準備中」は出さない | `gentesttier/tabs.templ` の `ComfyPanel` |

- 段の切り替えは、フォームの上のタブ（`nav[aria-label="作り方"]`。ページ間のタブ `generationNav` と同じ流儀: 今の段は `aria-current="page"` の `span`、他は `a`）。かんたん ⇄ こだわりは、フォームを**入力したまま**差し替える（HTMX。入力済みの値を `hx-include` で送り返し、`hx-push-url` でアドレスも変える）。スクリプトが無くても、ただのリンク（`?tier=`）で開ける（入力は持ち越さない）。ComfyUI は別の画面への入口なので、入力を持ち越さない普通のリンク。
- **動画のフォームには段が無い**（今のまま）。画像／動画の切り替えは、今までどおり `GET /generation-test/form`。
- プロジェクトの画像・履歴・ポーズ集から選ぶ入力画像、見積り → 確認 → 実行、進捗と比較表、履歴は、3 段とも同じもの（かんたんも `ConfirmBox`・`BatchBox` を使い、見積りを必ず先に出す）。

### 段の決め方（URL）

- `GET /generation-test?tier=easy|detail|comfy`。無い・知らない値は**かんたん**。`tier` はフォームの hidden（`input[name=tier]`）にもあり、見積りは `tier=easy` のときだけ、やりたいことからモデルを決める。確認の hidden はモデルを持つので、`tier` は持たない。
- モデルを**名指す**入口（`?model=`・`?from_result=`（プロンプトマッチの回）・`?again=`）は、`tier` を付けなければ**こだわり**で開く（かんたんはモデルを自分で選ぶ段なので、名指されたモデルが選ばれないため）。`?prompt=`（プロンプト履歴）と `?ref=`（結果の「入力画像として使う」）はモデルを名指さないので、**かんたん**で開く（プロンプト・入力画像が入った状態。入力画像があるので、画像を使えるモデルが選ばれる）。動画のモデルを名指したときは動画のフォームで、段は無い。
- `?again=<結果の id>`（＋`same_seed=1`）は §5 の復元。`?ref=…&ref_role=face&intent=face&tier=easy` は「この顔で作る」。

## 2. かんたん

- **やりたいこと**: 人物写真・アニメ・風景・同じ顔で（`input[type=radio][name=intent]`。選択肢のカードは `molecules/pick`）。選ぶと、その下の「使うモデル」と品質のボタンだけを `GET /generation-test/easy-pick` で差し替える（ブラウザで選んだ入力ファイルを壊さない）。
- **選択肢と各モデルの対応はデータ**（`backend/internal/service/gentest/intent/intents.json`。バイナリに埋め込む。理由は §7）。各選択肢は、モデルの**候補を好みの順に**持つ（カタログのワークフロー名。`flux1-dev` なら ID は `comfyui:bundled-comfyui/flux1-dev`）。選ぶのは、候補のうち次のすべてを満たす最初のもの（`gentest.Service.Recommend`）:
  1. **導入済み**で、今呼べる（`modelcatalog.Info.Available`。導入されていない・同梱エンジンが無いモデルは候補にならない）。
  2. 成人ゲート（`Hidden` = `modelmanager.HidesModel`）が閉じているあいだは、成人向けのモデルは**一覧に無い**ので選ばれない。
  3. 設定「商用OKのモデルだけを使う」のフィルター（`modellicense.DefaultFilter`）に合う（フィルターの意味は [../architecture/model-license.md](../architecture/model-license.md) §5）。
  4. この PC の OS・GPU が、モデルのカタログの列（`requires`・`unsupported`。#979）の外でない（警告があるものは選ばない。`Deps.PlatformWarning`）。
  5. 入力画像があるときは入力画像を使えるモデル（`reference_only` の img2img ワークフローは、入力画像があるときだけ候補になる）。「同じ顔で」は顔の役割（`face`）を読めるモデル。
- 候補に専用でないもの（アニメ向けが無いときの汎用モデル）が入っているときは、`note`（「アニメ専用のモデルが使えないため、汎用のモデルで作ります。…」）を**選ばれたモデル名の下**に出す。入力画像があるのに画像を使えないモデルしか無いときは、画像を使わない旨を添える。
- 選ばれたモデル名は小さく出す（`data-testid="gt-easy-model"`。「使うモデル: …」）。選ばれたモデルの `<li data-model>` のカード（見えない。こだわりのカードと同じ作りで `input[name=model]` を持つ）が、入力画像・詳細設定のスクリプトにモデルの性質を渡す。
- **該当モデルが 1 つも無いとき**: 理由（`data-testid="gt-easy-nomodel"`）と、モデルマネージャーへのリンク「モデルマネージャーを開く」。理由は、導入されていない（「「人物写真」に合うモデルが、まだ導入されていません。モデルマネージャーで導入してください」）か、導入済みだが条件に合わない（商用フィルター・OS・GPU・顔を読めない）かを言い分ける。見積りのボタンは押せない（`disabled`）。
- **品質**: 「速い／標準／きれい」の 3 ボタン（`input[type=radio][name=quality]`。`fast`・`standard`・`high`。既定は標準）。§3 のプリセットを使う。**プリセットを持たないモデルでは 3 ボタンを出さず、理由を出す**（`data-testid="gt-quality-reason"`）: ステップ数・CFG を受け取らない（クラウドのモデルなど）／速さのモードが決める（#973 の決定。Speed mode のあるモデルは steps・cfg を上書きできない）／プリセットが無い（4 ステップで作る蒸留モデルなど）。
- **サイズ**: 「縦／横／正方形」（`input[type=radio][name=aspect_ratio]`。`9:16`・`16:9`・`1:1` = こだわりの縦横比の入力と同じフィールドと同じ値）。こだわりで別の比（`4:3` など）にしてかんたんに戻っても、サイズは変わらない（その比が 4 つ目のボタンとして残る）。
- **入力**: プロンプト（`textarea[name=prompt]`）と入力画像（今の入力画像の区画をそのまま使う。ドロップゾーン・サムネイル・役割と強さ）だけ。ネガティブ・本数・英訳の設定は、フォームの hidden として**持ち越す**（かんたんで触れないだけ。こだわりで入れたものは、かんたんに戻っても消えない）。複数のプロンプトがあるとき、2 つ目以降も hidden で持ち越す。
- **何も触らずに生成すると、今と同じ品質のグラフ**（標準＝今のテンプレートの既定値）: 品質が標準（または無い）のとき、リクエストは steps・cfg を**何も上書きしない**（`Request.Quality` が空 = 上書きなし）。テンプレートのグラフが今までどおりに走る（`service/gentest/qualitytest` がグラフを比べて保証する）。
- 「**詳細設定を開く**」は、こだわりへ移る（`SwitchAttrs(detail)`）。かんたんで選んだ値は §4 のとおり持ち越す。
- 見積りは、かんたんでも**先に出す**。見積りの応答は、やりたいことからモデルを決めて見積もる（`tierform.Resolve` → `intentapply.Apply`）ので、確認の hidden には決まったモデル（`model`）が入り、「この内容で実行する」は見積りと同じリクエストを走らせる（モデルが途中で変わらない）。

## 3. 品質のプリセット（モデルごとの値）

- プリセットは**テンプレートのワークフローに持たせる**（`backend/internal/agent/modeladapter/localcfg/templates/image/*.json` の `workflow.quality_presets`）。理由は §7。形は `{"fast": {"steps": N, "cfg": C}, "high": {"steps": N, "cfg": C}}`（各項目は省ける。`steps`・`cfg` は #973 の `Param` が載る値）。**標準は書かない**: 標準 = そのワークフローのグラフが持つ値そのもの（上書きなし）。
- 値は mam の目安（モデルカード・テンプレートの既定から、速い = 既定より少ないステップ・きれい = 既定より多いステップに寄せたもの）で、**GPU では確かめていない**（`needs_real_device`）。`quality_presets` を持つテンプレート: SDXL 系（`txt2img-sdxl`・`-clipskip2`・`-controlnet`・`-ipadapter`・`img2img-sdxl`・`-clipskip2`: 速い 15・きれい 40。標準 25）、FLUX.1 dev（`txt2img-flux-dev`・`-lora`: 12・30。標準 20）、Chroma（16・40。標準 26）、Qwen-Image・Qwen-Image-Edit-2511（12・30。標準 20）、Qwen-Image 2.1（15・40。標準 25）、SD3.5 Medium（18・40。標準 28）。FLUX.1 schnell・FLUX.2 klein は 4 ステップで作る蒸留モデルなので**持たない**（3 ボタンの代わりに理由が出る）。インペイント・アップスケールのテンプレートも持たない。
- 読み込みの検査（`localcfg.ValidateModel`）: プリセットは、そのワークフローが受け取る値（steps・cfg の割り当て）にだけ書ける。速さのモードを持つワークフローは持てない。範囲は #973 と同じ。速いはワークフローの steps より少なく、きれいは多くなければならない（ボタンが言うとおりに動くため）。
- 効き方: リクエストの `quality`（`fast`／`high`）は、**リクエストが steps・cfg を名指ししていない項目だけ**にプリセットの値を入れる（`sampling.Caps.WithQuality`）。名指した値（こだわりのスライダー・MCP の `sampling`）が勝つ。受け取らないモデル・速さのモードのモデル・プリセットの無いモデルに `quality` を送ると、見積りの警告 `quality_ignored`（標準の値で作る）。標準を送るのは空と同じ。
- 結果に残るのは、実際に使った steps・cfg（`params.sampling`。#973）なので、品質の名前を別に残す必要は無い（結果の「使った設定」から作り直せる）。
- すでに導入済みのモデル（プリセットが入る前に作られたコピー）は、起動時の `wfrefresh` が、**テンプレートの steps から変えていないコピーだけ**プリセットを持つテンプレートへ更新する（利用者が steps などを編集していれば触らない）。

## 4. こだわり（詳細設定）

- 中身は今の作成フォーム（モデルのカード・プロンプトとネガティブ・パラメーター・**詳細設定（#973）**・入力画像・LoRA・参照画像の強さ）。**無い入力を新設しない**: ネガティブ・LoRA と強さ・参照画像の強さは、これまでの場所にあり、こだわりの上の「変えた項目」の欄が一箇所に集めて見せる。
- **かんたんで選んだ値が最初から入っている**: かんたん → こだわりのとき、選んだモデルがそのままカードで選ばれ、品質のステップ数・CFG が詳細設定のスライダー（「上書きする」が入った状態）に入る。入れた旨の 1 行（`data-testid="gt-carried"`。「かんたんで選んだ「速い」（モデル・ステップ数 15）を入れました。変えた項目には印が付き、元に戻せます」）が出る。標準のときは何も入れない（上書きしない = 標準）。入力済みの値（プロンプト・縦横比・入力画像・LoRA）は、段を替えても残る。
- **こだわりからかんたんに戻る**と、かんたんで選んだやりたいこと・品質が見つかる（`easy_intent`・`easy_quality`。リクエストは読まない。読むと、こだわりのスライダーの値を上書きしてしまうため）。
- **変えた項目に印**: 段が始まったときの値（かんたんで入れた値）と今の値が違う項目に「● 変えた」の印（`data-gt-mark`、`data-gt-changed`）が付く。対象: シード・ステップ数・CFG・サンプラー・スケジューラー・ネガティブ（プロンプトごと）・LoRA と強さ・参照画像の強さ（入力画像ごと。役割に追従する既定は、利用者が動かすまで「変えた」に数えない #960）。印は色だけにしない（文字つき）。
- **元に戻す**: 項目ごと（「◯◯を元に戻す」の小さなボタン）と全体（「全部を元に戻す」）。戻る先は、**段が始まったときの値**（かんたんで入れた値。無ければモデルの既定）。変えた項目の一覧（`data-testid="gt-refine-list"`、`aria-live="polite"`）が「ステップ数: 30（元は 15）」のように言う。変えた項目が無いときは「変えた項目はまだありません」と出す。規則は `refine-model.ts`（vitest）、DOM は `refine.ts`（web-test-runner）。
- 「レシピとして保存」は §9、「画面に出す値」の入力欄は §10、「プロンプトの語を選ぶと +/− が出る」は上の「語のウェイト」。

### 語のウェイト（強める + / 弱める −。Issue #977 の「3. こだわり」・#972 の任意項目）

プロンプトの語を選ぶと、`(語:1.2)` を**書かずに**入れられる小さなバーが出る。かんたんとこだわりのプロンプトの区画（`fieldset[data-testid=gt-prompt-fields]`）の中に `<mam-prompt-weight>`（`organisms/gentesttier/weightbar.templ`。部品は `static/src/components/prompt-weight/`）が 1 つ立つ。動画のフォーム（段が無い）には付けない。かんたんの区画の見出しには「プロンプトのウェイトの説明」の「?」（書き方と、ボタンの使い方・ショートカット）を置く（こだわりは今までの「ウェイト (語:1.3)」の「?」。モデルごとの行つき）。

- **出るとき**: `textarea[name=prompt]`（ネガティブには出さない。足したプロンプトの行にも効く）で語を選んだとき。選びを外す・別の所へフォーカスが移る・`Esc` で消える。バーは「選んだ語の強さ 1.0 倍」「強める +」「弱める −」と、範囲とショートカットの 1 行、モデルの注（`role="status"`）。
- **押すと**: 選んだ語を 0.1 刻みで変える。`語` → `(語:1.1)` → `(語:1.2)`。すでに `(語:1.3)` なら数字だけを変える（括弧ごと選んでも、中の語だけ選んでも同じ）。**1.0（その外側の強さと同じ）に戻ったら括弧ごと外す**。上限 **1.5**・下限 **0.5**（上限・下限では、そのボタンは押せない。範囲の外の数字を自分で書いてあるときは、範囲の端に戻す方向へだけ動く）。数字は 0.1 の丸めで持ち、足し算の誤差を残さない（`1.1` ＋ 0.1 = `1.2`）。
- **範囲 0.5〜1.5 の根拠**: ComfyUI の書式に上限は無いが、SDXL 系（CLIP）は **1.5 を超えると絵が崩れやすく**、0.5 を下回ると語がほぼ無視される、というのが AUTOMATIC1111・ComfyUI の利用者の間で広く言われる実用の範囲（このプロジェクトで GPU で確かめた値ではない。確かめていないので、範囲は `weight-model.ts` の `WEIGHT_MIN`・`WEIGHT_MAX` の 2 つの定数だけで決まり、変えるときはそこと、この節と、単体テストを直す）。
- **ComfyUI の読み方に合わせる**（`comfy/sd1_clip.py` の `token_weights`。#972 の `localcfg/promptweight`）: `(語:1.3)` は外側に関わらず 1.3、**`(語)` は外側の 1.1 倍**、`((語))` は 1.21 倍（バーは 0.1 刻みに丸めて 1.2 と読む）。`[語]` は読まれない（ただの文字。外側とは数えない）。`\(` `\)` はかっこそのもの（数えない）。`(語)` を押すと、1.1 の次は 1.2 なので `(語:1.2)` に書き換える（入れ子の `((語))` も 1 つの数字に直す）。外側の `(赤い 猫:1.3)` の中の `猫` に押すと、`猫` の強さは 1.3 から始まり、`(赤い (猫:1.4):1.3)` のように内側に付く（内側の数字が外側を置き換える。外側に戻れば外れる）。
- **選びの扱い**: 前後の空白は無いものとして扱う（ダブルクリックが後ろの空白まで選ぶため）。括弧の一方だけを含む選び・空の `()`・空白だけの選びは、変えられない（バーを出さない）。**押したあとは、変えた部分全体（`(語:1.2)`）が選ばれたまま**になるので、続けて押せる。変えた文字数が `maxlength` を超えるときは、変えずに理由（文字数の上限）をバーに出す。
- **キーボード・a11y**: ボタンは本物の `<button>`（Tab で届く。`mousedown` は既定動作を止め、マウスで押してもテキストエリアの選びとフォーカスを壊さない。Tab でボタンに移っても、テキストエリアの選びはそのまま残り、バーも残る）。テキストエリアの中では **Ctrl（⌘）+ ↑ で強める・Ctrl（⌘）+ ↓ で弱める**（ComfyUI の画面と同じ）。押せないボタンは `aria-disabled="true"`（フォーカスは残り、理由の注に `aria-describedby` でつながる）。注は `role="status"`。テキストへの書き込みは、フォーカスがテキストエリアにあるときは `execCommand("insertText")`（ブラウザの「元に戻す」が効く）、なければ `setRangeText`。どちらも `input` イベントを出す（こだわりの「変えた」の印・文字数が追従する）。
- **モデルごとの「効く・効かない」**（Issue #972・#1023）: モデルのカードは `data-prompt-weight`（`supported` / `weak` / `unsupported` / `unknown`）と `data-prompt-weight-title`（短い言葉。`settingsview.WeightTitle`: 「効きます」「効きが弱いかも」「効きません（代わりに文で強調してください）」「未確認」）と `data-label`（**表示名**。カードの名前と同じ。識別子は出さない）を持つ。部品はこれを、フォームの中の**選ばれたモデル**（かんたんの隠しカードも）から読む（`chosen-models.ts`・`weight-facts.ts`）。**選ばれたモデルが全部 `unsupported`**: バーは出すが、**ボタンは押せず**（Ctrl+↑↓ も何もしない）、注に理由（「（モデル名）では、ウェイト (語:1.3) は効きません。強調したい語は、文で言い換えてください」）が出る。**`weak`**: ボタンは使え、「（モデル名）: 効きが弱いかも」の注が付く。**`unknown`（未確認）**: ボタンは使え、バーに注は付けない（長い同じ文を繰り返さない）。**`supported`**: 注なし。複数のモデルを選んでいるときは、同じ読み方のモデルを 1 行にまとめて名前を並べ（各名前は 1 回）、1 つでも読むモデルがあればボタンは使える。モデルが選ばれていない間は何も言わず、使える。モデルの選びが変わる（かんたんの「やりたいこと」・こだわりのカード・商用フィルター・htmx の差し替え）と追従する。
- **効かないモデルの注意と「?」のヘルプ**（Issue #1023）: プロンプトの入力欄のすぐ下（かんたん・こだわり共通）に `<mam-weight-note>`（`organisms/gentesttier/weightbar.templ` の `WeightNote`。`[data-testid=gt-weight-caution]`）が立ち、**選んでいるモデルのうち `unsupported` のものがあるあいだだけ**、その名前つきで「ウェイト (語:1.3) は効きません。強調したい語は、文で言い換えてください（「特に」「とても」を付ける、先頭に置く、など）」と 1 つの短い注（`role="status"`、`text-amber-300`）を出す（ヘルプを開かなくても分かる）。「ウェイト (語:1.3)」の「?」の中は、書き方の説明と、`<mam-weight-help>`（`[data-testid=gt-weight-help]`）が描く**いま選んでいるモデルの分だけ**（同じ読み方のモデルを 1 行に: 「Qwen-Image: 効きません（代わりに文で強調してください）」「SDXL base: 効きます」「Nano Banana: 未確認」。選んだモデルが無いときは「モデルを選ぶと、ここに効き方が出ます。」）。こだわりの「?」には、その下に折りたたみ「すべてのモデルを見る」（`details[data-testid=gt-weight-all]`）があり、フォームにある全モデルを読み方ごとに 1 行、表示名で出す（各言葉は 1 回。サーバーが描く）。かんたんの「?」は選んだモデルの分だけ（折りたたみなし）。**モデルの表示名**は、モデルマネージャーのカタログの名前（`catalog.Model.Name`。同じ項目が複数のワークフローを持つときは `SDXL base（img2img）` のように違いを括弧で足す。`mmview.DisplayName`）で、カタログが知らないローカルモデル（外部の ComfyUI など）はモデル名だけ（`comfyui:<接続先>/` は付けない）。クラウドのモデルは今までどおりモデル名。
- **htmx の差し替え**: 部品は `connectedCallback` で区画とフォームのリスナーを付け、`disconnectedCallback` で外す。差し替えられたフォームには新しい要素が立つ（履歴のスナップショットに残った描画済みのバーは、立ち上がりのときに捨てる）。バーは光らせず、既存の色だけ（`border-neutral-700`・`bg-neutral-900`・`text-amber-300` など。[color-rules.md](color-rules.md)）。
- **実機**: 実ブラウザでの見た目（バーの置き場所・狭い画面での折り返し）は `needs_real_device`。

## 7. 判断した点

- **URL はクエリ（`?tier=`）**: 段は同じ画面（`/generation-test`）の状態で、パスを分けると、戻る・入力の持ち越し・既存の入口（`?model=` など）が複雑になる。ブラウザの戻る・リロードで同じ段に戻れるよう、段を替えるとアドレスも変える（`hx-push-url`）。
- **プリセットはテンプレート（ワークフロー）に持たせる**: モデルの性質（steps の既定・蒸留かどうか・どの値が速さに効くか）は、そのグラフと一緒に決まり、テンプレートを足すとき（`localcfg/templates/**`）に同じ場所で直せる。モデルのカタログ（`modelmgr/catalog/data/models`）は「何をダウンロードするか」のデータで、複数のワークフローが同じモデルを別の steps で使い（SDXL の txt2img と img2img など）、導入済みのモデルが持つのは**ワークフロー**なので、カタログに置くとグラフの値と二重管理になる。`Caps`（`list_generation_models` の `sampling`）に載るので、画面と MCP は同じものを読む。
- **選択肢と対応するモデルのデータは `service/gentest/intent/intents.json`（埋め込み）**: 「やりたいこと → 候補モデル」は**生成テスト（画面と MCP）の選び方**であって、モデルの導入データ（`modelmgr/catalog`）でも、モデルのワークフロー（`localcfg`）でもない。カタログの流儀（埋め込み JSON を `DisallowUnknownFields` で読む）に合わせ、選択肢や候補の追加は JSON の編集だけで済む。候補はカタログのワークフロー名で書き、テスト（`TestTheIntentsNameWorkflowsOfTheCatalog`）が、実在しない名前を許さない。
- **`quality` は `Request` の 1 項目**（画面の hidden・MCP の引数・見積りの検証が同じ形）。リクエストが steps・cfg を名指ししていればそちらが勝つ（こだわりの値が勝つ）。

- **こだわり → かんたんで詳細設定が消えることは、消すと**画面で言う**（保持しない。Issue #1000）**: かんたんは「何も触らなくても今と同じ品質」が約束で、フォームは詳細設定の欄（seed・steps・cfg・sampler・scheduler・画面に出す値）を持たない。保持するには、かんたんのフォームが hidden でそれらを運んで実行に混ぜる（かんたんで生成した結果が、見えない値で変わる = 約束が壊れる）か、別名の欄で運んでこだわりへ戻るときだけ復元する（欄が倍になり、かんたんで品質ボタンを押したあとの値との優先順位が要る）必要があり、どちらも「元に戻す」の基準（段が始まったときの値）を複雑にする。**消すと言うほうが、約束を守れて単純**。かんたんへのタブを押すときに、ブラウザ（`refine.ts`）が、こだわりで変えた項目のうちかんたんが持たないもの（seed・steps・cfg・sampler・scheduler・画面に出した値）のキーをリクエストに足し（`dropped`。`droppedKeys`）、返ってきたかんたんのフォームの冒頭に「こだわりで変えた詳細設定（シード・ステップ数）は、かんたんでは使わないため消えました。こだわりへ戻っても元には戻りません」と出す（`tierform.State.DroppedNotice`）。プロンプト・ネガティブ・LoRA・入力画像の強さはかんたんが持つので、言わない。何も変えていなければ何も言わない。品質ボタンの値（steps/cfg）は `easy_quality` で運ぶので、変えていなければ消えない。スクリプトが無いリンクの移動は入力ごと持ち越さないので、言うことが無い。

## 9. レシピ（Issue #977 ステージ 2）

**レシピ＝「今の設定」に付けた名前。** 画像のこだわり（`tier=detail`）の末尾に「レシピ」の区画（`data-testid="gt-recipe-section"`。`organisms/gentesttier/recipe.templ`）があり、保存・一覧・名前の変更・かんたんへの足し外し・削除ができる。保存先は SQLite の表 `gentest_recipe`（マイグレーション `20261104100000_gentest_recipe.sql`。[../architecture/gentest/er-gentest.md](../architecture/gentest/er-gentest.md)）、サービスは `service/gentest/recipe`、画面のルートは `web/handler/gentest/recipescreen`。

- **何を保存するか**: モデル（ワークフロー名＝モデル ID）・ステップ数・CFG・サンプラー・スケジューラー・シード（**固定しているときだけ**値）・ネガティブ・LoRA と強さ・参照画像の強さ・縦横比（サイズ）・品質・速さのモード（`speed_mode`。保存時にそのモデルが持つモードだけ。無いモードは 422）・「画面に出す値」（§10）。**プロンプトの本文と入力画像は保存しない**（保存するのは入力画像に付けた強さだけ）。保存はモデル 1 つのフォームだけ（複数のモデルのときは理由つきで拒否）。値の検査は生成のリクエストと同じ（範囲外は 422）。
- **名前**: 1〜60 文字の 1 行、大文字小文字を区別せず一意（重複は 409）。件数は 200 件まで。
- **一覧**（`data-testid="gt-recipe-list"`）: 名前・モデル名・「かんたんに出ています」の印と、「使う」「名前を変える」「かんたんに出す / かんたんから外す」「削除」（確認つき）。操作は区画 `#gt-recipes` だけを差し替える（`POST /generation-test/recipes` ほか。[../api/endpoints-gentest.md](../api/endpoints-gentest.md)）。
- **「使う」**: `GET /generation-test?tier=detail&recipe=<id>`（フォームの差し替えは `GET /generation-test/form` に同じクエリ）。モデルを選び、詳細設定・LoRA・速さのモード・縦横比・画面に出す値を入れる（モデルが今そのモードを持たないときは、既定のまま「このモデルにないため既定で作ります」と言う）。**今のプロンプト・入力画像は変えない**。ネガティブは、空のプロンプトにだけ入れ、強さは、強さを持たない入力画像にだけ入れる。レシピが品質（速い／きれい）を持ち、ステップ数・CFG が無いときは、そのモデルのプリセットの値を詳細設定に入れる（かんたん → こだわりと同じ `tierform.Carry`）。
- **かんたんの選択肢**: 「かんたんに出す」にしたレシピは、かんたんの「やりたいこと」の下に「保存したレシピ」として並ぶ（`data-testid="gt-recipe-choices"`。選択肢の値は `recipe:<id>`、見た目は `molecules/pick` で、やりたいことと同じ）。選ぶと、`easy-pick` の区画が**そのモデル**と「レシピの設定で作ります」の行に変わり（品質のボタンは出さない: レシピが steps・cfg を持つ）、サイズのボタンは**レシピのサイズ**に変わる（`hx-swap-oob`）。見積りは、モデルと設定をレシピから決める（`tierform.Resolve` → `recipe.Service.Apply`）ので、確認の hidden にレシピの値が入り、実行は同じリクエストを走らせる。かんたんからこだわりへ移るときも、選んだレシピの設定が入る。
- **使えないレシピ**: モデルが削除された・導入されていない・今は呼べない・成人ゲートが閉じている・設定「商用OKのモデルだけを使う」や OS・GPU の条件に合わないときは、**消さずに**、一覧に「使えません: 理由」（`data-testid="gt-recipe-reason"`）を出し、「使う」を出さない。かんたんの選択肢には理由つきで残り、選ぶと「レシピ「…」は使えません: …」を出して見積りを押せなくする。成人ゲート・商用の絞り込み・OS／GPU の判定は、かんたんのやりたいことと**同じ関数**（`Service.Model` と `intent.Excluded`）を使う。
- **成人ゲートが閉じているとき（Issue #992）**: 成人向けモデルのレシピは、一覧・かんたんの選択肢・MCP の一覧のどれにも、モデルの名前や設定（ネガティブ・LoRA・画面に出す値など）を出さない。モデル名の欄は「成人向けのモデル」、理由は上の「成人ゲートが閉じている」の文言で、レシピの名前・「かんたんに出ています」の印・削除はそのまま使える。「使う」は出さず、かんたんで選んでも設定は入らない。ゲートを開くと元の表示に戻る（保存した設定は消えていない）。
- **MCP**: `list_generation_recipes`・`save_generation_recipe`・`update_generation_recipe`・`delete_generation_recipe`、`estimate_generation_test`・`run_generation_test` の `recipe`（[../api/mcp-tools-generation-test.md](../api/mcp-tools-generation-test.md)）。

## 10. ComfyUI の段（Issue #977 ステージ 2）

### 10.1 今の設定を ComfyUI で開く

- **ボタン**: 「今の設定を ComfyUI で開く」（`data-testid="gt-comfy-open-button"`）が、かんたんの下端とこだわりのレシピの下にある。フォームの値（モデル・プロンプト・縦横比・シード・ステップ数などの詳細設定・LoRA・画面に出す値。かんたんならやりたいことから決めたモデルと品質）で**そのモデルのグラフを組み**（`comfyui.GraphFor`。実行と同じ組み立て: 割り当て・LoRA・画面に出す値を適用）、ノード画面で開く。`POST /generation-test/comfy/open`。
- **渡し方**: ノード画面にグラフを直接渡す口は無い（ComfyUI のフロントエンドは、サーバーの `workflows` フォルダのファイルを開く）。そこで、既存の「ワークフローをノード画面で開く」（[../architecture/comfy/comfy-workflows.md](../architecture/comfy/comfy-workflows.md) §3）と同じ流れで、グラフを**画面の形式**（ノードの位置・ウィジェットの値の並び・リンクの表。`service/workflows/graphui` が、API 形式と `GET /object_info` から組む。独自のグラフエディタではない）に直し、ComfyUI のユーザーデータ `workflows/mam/今の設定 <モデル名>.json` へ置いて（`Service.OpenUI`。同名は上書き）、`HX-Redirect` でノード画面（`/nodes?opened=…`）へ移る。ノード画面が置いたファイルの場所を案内する（左の「ワークフロー」から開く）。mam のワークフローとしては**保存しない**（保存は「ワークフローを取り込む」で）。
- **入らないもの**: 入力画像（読み込みのノードのファイルはワークフローのまま）と、英訳（プロンプトは入力したまま）。画像なしでは動かないワークフロー（ControlNet・IP-Adapter・部分描き直しの入力画像とマスク）は、その読み込みのノードと、それにつながるノード（ControlNetApplyAdvanced・IPAdapterAdvanced・VAEEncode・SetLatentNoiseMask・ImageCompositeMasked）を削らず、テンプレートが持つファイル名のまま出す（必須の入力が欠けたグラフを出さない。ノード画面で利用者が差し替える）。編集モデルの参照枠（任意）と img2img の参照は、画像なしの実行と同じく外し、文字だけから作る形で出す。ボタンの隣の結果欄ではなく、移った先の案内にも、この 2 点を出す。
- **開けないとき**: モデルが 1 つでない・ComfyUI のワークフローでない（クラウドのモデル）・ComfyUI が止まっていて起動できない・ノードの情報が取れない、など。理由を `#gt-comfy-open`（`aria-live="polite"`）に出し、フォームは壊さない。
- 動画のフォームには出さない。

### 10.2 画面に出す値（`exposed_inputs`）

- **何か**: ワークフロー（テンプレート・取り込んだワークフロー・保存したワークフロー）に持たせる「**加算的な汎用入力**」（`localcfg/exposed`。[../architecture/local-models.md](../architecture/local-models.md) §4.8）。ノード ID＋入力名＋型（`int`/`float`/`string`/`enum`）＋範囲（int・float は `min`・`max`）または選択肢（enum）＋表示名。**今の割り当て（`assignments`）は変えない**。`exposed_inputs` が無いワークフローは今と同じに動く。入力の現在値（グラフが持つ値）が既定値。
- **選べない入力**: ほかのノードがつないでいる入力（リンク）・割り当てが使っている入力（プロンプト・シード・サイズ・ステップ数など。こだわりの詳細設定にある）・真偽値・リストは選べない（保存時に拒否し、選ぶ画面では理由を出す）。
- **選ぶ画面**: ComfyUI の段の「画面に出す値を選ぶ」（`GET /generation-test/comfy/exposed`。`data-testid="gt-comfy-exposed"`）。モデル（ComfyUI のワークフロー）を選ぶと、そのグラフのノード・入力が表になり、チェックを入れて名前と範囲を決めて保存する（`POST /generation-test/comfy/exposed`。`service/gentest/exposedpick`）。型・範囲・選択肢は、ComfyUI が答えれば `GET /object_info` から、答えなければグラフの値から決める（止まっている同梱の ComfyUI は、ここでは起動しない）。選べない入力は表の下の「選べない入力と、その理由」に出る。グラフエディタは作らない。保存先は、モデルの置き場所に応じて、保存したワークフロー（`comfy_workflow`）か、接続先のモデル（`models.json` の `local_models`。同梱の ComfyUI の導入モデルと、取り込んだワークフロー）。設定ファイルが固定されている（`--model-config`）ときは、保存できない旨を出す。
- **MCP からの設定**: `import_workflow_json`・`update_workflow_assignment`（`settings.exposed_inputs`）、`create_local_model`・`update_local_model`・`get_local_model`（`exposed_inputs`）。`update_workflow_assignment` が `exposed_inputs` を省くと、今の値のまま。
- **こだわりの入力欄**: そのモデルを選ぶと、詳細設定の中に「◯◯ の「画面に出す値」」の組（`data-gt-exposed-model`。モデルを選んでいるときだけ表示し、選んでいないモデルの欄は無効にして何も送らない。`static/src/components/gentest-tiers/exposed.ts`）として、型に合う入力欄が出る: int・float は数値（`min`〜`max`）、enum は選択、string は 1 行か複数行。**空欄＝グラフの値のまま**（プレースホルダーに既定値）。フォームの名前は `exposed.<ノード ID>.<入力名>`。
- **生成**: リクエストの `exposed`（キー `<ノード ID>.<入力名>`）は、モデルの `exposed`（`list_generation_models`。`default` はグラフの値）に照らして**型・範囲・選択肢を検査**し（範囲外・どのモデルにも無いキーは 422）、そのキーを持たないモデルには警告 `exposed_ignored` を出して使わない。実行は、グラフを作るとき**最初に**値を入れる（割り当ての前。割り当てと重ならない）。使った値（指定しない項目はグラフの値）は結果の `params.exposed` に残り、結果の「使った設定」・詳細の表に出て、「この設定でもう一度」「似た感じでもう1枚」で入力欄に戻る。
- 画像だけ。実機の ComfyUI と GPU では確かめていない（偽の ComfyUI で、グラフに値が入るところまで）。
