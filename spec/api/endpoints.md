# API 仕様

HALT の3ルートパターン（`spec/architecture/overview.md` §7）に従う。ページルート/アクションルートは Gin が HTML（フルページ or フラグメント）を返し、`/api/v1` は Huma が JSON（OpenAPI 3.1 自動生成、`/api/v1/openapi.json`）を返す。JSON API は主に Lit Web Components（`mam-video-player` / `mam-timeline-editor` / `mam-take-comparator`）向け。

## 0. 認証・共通仕様

- 単一ユーザー・ループバック限定（`127.0.0.1`）のため外部向け認証は行わない。すべてのリクエストに CSRF トークン（meta タグ由来）を付与する（`spec/requirements/non-functional.md` §5）
- ファイルを返すルート（アセット・Take の動画とサムネイル・Edit Timeline のプレビュー・Export の動画・レビューの動画）は `Content-Security-Policy: sandbox` を付ける（`serveMedia` など）。`X-Content-Type-Options: nosniff` は全応答に付く（`SecurityHeaders`）
- 外部生成モデル API のキーはサーバー側（`agent/modeladapter`）でのみ保持し、フロントエンドには一切露出しない。画面の `<form hx-post>` はすべて、送信中の再送信を捨て（`hx-sync="this:drop"`）、送信ボタンを無効にする（`hx-disabled-elt`。チャット入力欄は入力を続けられるよう `hx-sync` のみ）ので、作成系の二重作成や 2 回目の誤ったエラートーストは起きない。`backend/internal/web/double_submit_test.go` が `.templ` 全体（`organisms/worldstate/` のようなサブディレクトリも再帰的に）を走査して漏れを検出する（`hx-trigger="change"` のフォームは対象外）
- エラーレスポンスは HALT の方針（`spec/architecture/overview.md` 参照元 `skill://halt`）に従う:
  - ページ/アクションルートのバリデーションエラー（422）: フォームをエラー付きで再レンダリング
  - ビジネスエラー（403/409/423等）: OOBスワップでトースト表示。変更でその場保存するコントロール（`hx-trigger="change"` のラジオ・セレクト・チェックボックスを持つ `<select>` / `<form>`: MODE、Production Template、Quality、Confirmation Level（確認レベルの select と CUSTOM CHECK の確認ポイントの checkbox を持つ 1 つのフォーム）。`<form>` は `reset()` でフォームごと戻る）は送信前に選択が変わっているため、失敗（422・403・5xx・通信断・タイムアウト）の後にクライアント（`static/src/components/save-on-change/`）が `htmx:afterRequest` で保存済みの値に戻す
  - APIルートのエラー: Huma による RFC 7807 Problem Details。ルートに一致しない URL（404）とメソッド違い（405）も、`/api/v1` 配下は同じ Problem Details（`application/problem+json`）で、それ以外はページルートの存在しない対象と同じ応答（レイアウト付きの `ErrorPage`、`HX-Request` では `HX-Reswap: none` のトースト。どちらも文言に URL を含める）。gin 既定の素のテキストは返さない
  - 共通ミドルウェアが Huma より前に返すエラー（非ループバック・CSRF 不一致の 403、本文上限の 413、読めない urlencoded フォームの 400）は `/api/v1` でも Huma と同じ RFC 7807 の `application/problem+json` `{"status": number, "title": string, "detail": string}`（`detail` は HTMX のトーストと同じ利用者向けの文言で、Lit の `errorMessage()` がそのまま表示する。理由が無いときは空本文）。HTMX リクエストにはトーストを返す。読めない `multipart/form-data` の 400 と、アップロードルートの multipart の 413 はこのミドルウェアではなく、`readMultipart` を呼ぶ各ハンドラが他のビジネスエラーと同じ表示（トースト、フォームを持つルートはエラー付きの再描画。JSON ではない）で返す
- 共通ビジネスエラーコード（400・413・402・403・404・409・423・422・429・500・502・503）: [errors.md](errors.md) を参照

M1 の入出力契約（Issue #12）:

- `PUT /projects/:id/mode`: Body `mode`=`auto|director`。応答は MODE コントロール（`chat_composer` 内）のフラグメントで、`HX-Trigger: chat:refresh` によりスレッドに追記された AI 発言（モード切替の通知）を取得させる。不正値は 422、存在しない Project は 404。DIRECTOR の間はパイプラインが工程を進めない（指示した箇所だけを直して待機する）。AUTO に戻すと、DIRECTOR 中に止まっていた工程から再開する。モードは `project.mode` に保持され、切替でほかの状態は変わらない
- `PUT /shots/:id/locks`: Body `parameter`（`dialogue|character_identity|acting|camera|lighting|product_geometry|prompt|video_model|take_selection|editing`）と `mode`（`auto|manual|lock`）、`video_model` のみ `value`（`kling-3.0|seedance-2.0|runway-gen-4.5`）。応答は当該パラメータの `lock_toggle` フラグメント。`video_model` は MANUAL でモデル名が必須、LOCK で省略時は最新 Take のモデルを固定する。すでに LOCK 中の値を別の値で LOCK し直す要求は 423。不正なパラメータ/モードは 422、存在しない Shot は 404。`lock` に行が無いパラメータは AUTO
- `PUT /projects/:id/locks`: Body `target_type`（または `parameter`）=`story|music` と `mode`。Story を LOCK すると State Extractor は Story の全項目を変更しない。Shot のパラメータは 422、存在しない Project は 404
- `PUT /shots/:id/shot-spec`: Body `shot_spec` は Canonical Shot Spec の JSON（未知のキーは 422。`duration` は Shot の長さに固定）。`domain.ShotSpec.Validate` を満たさない入力は 422 でフォームを入力値と理由付きで再描画。LOCK 中のパラメータの部分を変える編集は 423 で何も書かず（Prompt を LOCK した Shot は Spec のどの部分も変えられない）、生成中の Shot は 409。成功時は新しい `prompt_version` を追記して、Shot Spec の領域（`#shot-spec`。Inspector 全体は返さず、演出指示や Reference Pack の追加の書きかけの入力を消さない）を返し、バージョン履歴（`#version-history-shot-<id>`）を `hx-swap-oob` で添える。422 も同じ領域を入力値と理由付きで返す
- `GET /shots/:id`: `HX-Request` でフラグメント、なければフルページ（`shot_inspector_page`）。Canonical Shot Spec・Take List・全パラメータの AUTO/MANUAL/LOCK 切替・Spec の手動編集フォーム・自然言語の指示フォームを表示する
- `POST /shots/:id/director-command`: Body `content`（必須、4000 文字以内。超過は 422。`POST /projects/:id/messages` と同じ上限）。Command Interpreter が返した操作を実行する。順序は LOCK 設定 → 再生成 → モード切替。再生成は対象 Shot だけを起動し（202、他は 200）、変更する部分以外（Character/Acting/Environment 等）と LOCK 中の部分は Shot Spec に引き継ぐ。LOCK 中の部分を変える再生成を含む指示は 423 で、発言も記録せず何も実行しない（同じ指示の中で LOCK を外していれば許可）。LLM 未構成は 503。同じ Shot への指示がまだ処理中のとき（二重クリック・別タブ）は 409 で、有料の Interpreter 呼び出し・発言の記録・再生成や Branch の作成を重ねて行わない（画面のフォームも送信中は送信ボタンを無効にし、進行中の再送信を捨てる。`hx-sync="this:drop"`・`hx-disabled-elt`）。発言と結果は AI 発言としてスレッドに記録される。時間範囲を名指しした指示（`partial_regenerate`、M2）は `job.kind=repair` を起動する（202）: Shot 全体を新しい Take として作り、その区間だけを Shot の選択 Take（なければ AI Pick、なければ最新の除外されていない Take）に差し替えた候補 Take をもう 1 本足す。既存の Take は変わらず、Retry Policy の再試行回数には数えない（予算上限は適用）。ffmpeg が無い・元にできる Take が無い・Shot が生成中のときは何も作らず、その旨を AI 発言に記録して 200
- `POST /projects/:id/messages`: DIRECTOR MODE で Brief 確定後（DRAFT 以外）の発言は Command Interpreter が解釈する（Approval / Question / Escalation カードへの返信は従来どおりその回答）。対象 Shot は「Take または Keyframe カードへの返信（Keyframe はその画像を Reference Pack に持つ Shot。解決できなければ他の Shot にせず聞き返す） → 発言中の Scene/Shot 番号 → スレッドの直近の Take カード → Shot が 1 つだけの Project」の順で解決し、解決できなければ AI が聞き返して何も実行しない。LOCK 中の部分を変える再生成は実行せず、AI 発言でその旨を伝える。Branch 作成の指示は `create_branch` として実行する（§2.4。`count` 1〜5。指示のない分は Continue Agent の NEXT 候補で埋め、各 Branch の最初の Shot を生成する）
- `POST /shots/:id/generate`: `additional_instruction` を伴う要求は、Prompt が LOCK された Shot では 423。LOCK / 指示で保持する部分は Shot Spec を作り直す際にも変更されず、`video_model` が MANUAL/LOCK の Shot はそのモデルだけで生成する（長さやコストによる別モデルへの切替は行わない）

**Take System の動作（M1）**

- AI Pick: Judge が結果を保存するたびに、その Shot の Take のうち Judge 済みで除外されていないものから最良を `ai_pick` にする（PASS が FAIL より先、次に 4 スコアの平均、同点は古い方。Retry Policy の Minimum acceptance score を満たす Take が 1 本でもあれば、候補はその Take だけで、基準未達の Take は平均が高くても AI Pick にならない）。ユーザーが Selected にした Take があれば何もしない。AUTO MODE で Shot の Take Selection が AUTO のときは、PASS かつ Minimum acceptance score を満たした AI Pick を Shot の Take（`selected_take_id`）にもする（PASS でも基準未達なら AI Pick にはなるが採用しない）。DIRECTOR MODE、または Take Selection が MANUAL / LOCK の Shot では推奨のみで、確定はユーザー（`POST /takes/:id/select`）。変更があったときは Judge のチャット通知に「AI Pick: …」を追記する。
- Take カード（`ref_type=take`）の本文 JSON は `video_url`（`/takes/:id/video`）・`poster_url`・`shot_id`・`fps`（カード作成時に ffprobe で 1 回読んだフレームレート。ffprobe がなければ省略）を持ち、`mam-video-player` を埋め込む（Templ は `fps` があれば `fps` 属性に渡す。なければプレイヤーが再生中に計測する）。Judge 要約と Take 状態（AI Pick / 採用 / 除外）はカードに載せない（スレッドは追記のみのため）。Judge が結果を保存するたびに別のテキスト発言として投稿される。カードには返信と Take 比較（`GET /shots/:id/takes`）への導線がある。
- `GET /shots/:id/takes` は `mam-take-comparator`（`api-url` に `GET /api/v1/shots/:id/takes`）を置くページ。部分採用が確定するとコンポーネントが `partial-take-confirmed` を発火する。

M2 の入出力契約（Issue #18 Branch）:

- `POST /shots/:id/branch`: Body は `application/x-www-form-urlencoded`。`point_type`（`scene|shot|frame`、省略時 `shot`）、`offset_seconds`（`frame` のときのみ。0 以上・Shot の長さ以内、外れれば 422）、`name`（省略時は指示文、なければ「Branch N」。100 文字以内）、`direction`（省略可。1000 文字以内、超えれば 422。指定すると Continue Agent が Branch 最初の Shot を計画して生成する。生成が未設定なら 503）。分岐点の World State を Snapshot として Branch 独自の `world_state_version` v1 に保存し、201 と `HX-Redirect: /branches/:id` を返す。分岐点が Branch 内の Shot なら、その Branch の子 Branch になる
- `GET /branches/:id`: `HX-Request` で詳細フラグメント（`branch_tree` の各項目が `hx-get` で取得して `#branch-detail` へ差し込む。応答には選択中の Branch を示したツリーを `hx-swap-oob` で同梱する。分岐点・親 Branch・Branch 独自の Scene/Shot・バージョン履歴（「履歴を開いて復元する」で `GET /branches/:id/versions` を差し込み、復元ボタンから Branch 自体・Branch の World State 系列を戻せる。復元の応答は `HX-Trigger: branch-reload` を付け、詳細とツリーを読み直させる）・`/projects/:id/world-state?branch_id=` への導線）、なければ Branch ツリー付きのフルページ。`GET /projects/:id/branches` は選択なしのツリーページ
- `PUT /branches/:id`: `name` と `world_state_version`（その Branch 自身の World State 系列の番号）の少なくとも一方。応答は詳細フラグメントと、新しい名前を反映した Branch ツリー（`hx-swap-oob` で `#branch-tree` を置換）。変更があれば `branch_version` に 1 行追記する（変化なしは追記しない）。系列にない番号・空の名前は 422、不明な ID は 404
- Branch は `scene` / `character` / `product` / `location` / `world_state_version` を独自に持ち（`branch_id`）、Branch の Shot の生成・State Extractor・編集はその Branch の行だけを更新する。トランクや他の Branch には影響しない。チャットスレッドは Project に 1 本で Branch では分けない

M1 の入出力契約（Issue #8）:

- `PUT /projects/:id/characters|products|locations/:entityId`: Body は `application/x-www-form-urlencoded`。編集できる項目は Character が `hairstyle/wardrobe/voice/personality/emotion/position/current_action`、Product が `material/orientation/condition`、Location が `time/lighting_state/weather`（各 200 文字以内、前後の空白は除去）。送った項目だけを更新し、空文字は項目のクリア。応答は更新した項目の編集フォーム（`#ws-form-<種別>-<id>`）だけ（200。画面全体は返さない）で、版数表示とバージョン履歴を `hx-swap-oob` で添える。新しい `world_state_version` を追記する。エラーはトースト（`HX-Reswap: none`）: LOCK 対象を1項目でも含むと **423** で全体を拒否（何も書き込まない）、更新項目なし・未知の項目・長すぎる値は 422、Project または当該 Project のエンティティが無ければ 404。画面（`world_state_view`）は、編集できる項目がすべて LOCK のエンティティには「保存」を描画せず、「すべての項目が LOCK 中のため編集できません。」の説明（`data-entity-edit-blocked`）を出す（`disabled` の入力は送信されず、押すと必ず上の 422 になるため。Shot Inspector が Shot の状態でフォームを出し分けるのと同じ）
- `GET /projects/:id/world-state`: `HX-Request` でフラグメント、なければフルページ（`world_state_page`）。LOCK 中の項目は「LOCK」バッジ付きで編集不可。Camera/Story は Shot 完了ごとに State Extractor が更新するため参照専用
- `branch_id` クエリ（`GET /projects/:id/world-state` と `POST /projects/:id/world-state/versions/:versionNumber/restore`）は、当該 Project の Branch を指すときだけ有効で（Issue #18）、存在しない Branch は 404。省略時は主系列（トランク）

M2 の入出力契約（Issue #15）:

- `PUT /projects/:id/world-state/locks`: World State の項目ごとの AUTO/LOCK 設定。Body `target_type`（`character|product|location|camera|story`）、`target_id`（Character/Product/Location の ID。`camera`/`story` は省略）、`parameter`（`spec/architecture/er.md` §4 の属性名）、`mode`（`auto|lock`）。応答は切り替えたスイッチ自身（200。画面全体は返さない）で、LOCK の状態に依存する入力欄と保存ボタン（Character/Product/Location）または Camera/Story の参照専用値を `hx-swap-oob` で添える。他の項目の未保存の入力と開いている LOCK 設定は保たれる。LOCK 中の項目は State Extractor が更新せず、ユーザー編集は 423。未知の `target_type`/`parameter`/`mode` は 422、存在しない Project・エンティティは 404。Story 全体の LOCK は従来どおり `PUT /projects/:id/locks`
- `PUT /projects/:id/characters|products|locations/:entityId/reference`: ライブラリの画像を World State の参照に割り当てる。Body `slot`（Character は `face|body`、Product は `geometry|label`、Location は `layout`）、`reference_id`（`reference_item.id`。空文字で割り当てを外す）。応答は当該スロットのフォームだけ（200）で、版数表示とバージョン履歴を `hx-swap-oob` で添える。新しい `world_state_version` を追記する。対応する LOCK（`spec/spec.md` §10.1）が掛かっていれば 423、`slot` が種別に合わない・`reference_id` の種別がスロットに合わないは 422、Project/エンティティ/`reference_id` が無ければ 404
- `GET /projects/:id/world-state` の各項目には LOCK の状態（`world_state_field` の LOCK バッジと `lock_toggle`）を表示する

入出力契約（認証は行わない。共有物の中身と除外は `spec/spec.md` §27.1、`spec/requirements/non-functional.md` §5）:

- `POST /projects/:id/reviews`: 成功時は、メモを空にした依頼フォームと、新しい依頼のカード（`#review-list-items` の先頭に差し込む。依頼が 1 件もなかったときの空の文言は消す）だけ（201。応答を取り込むフォームは返さず、選んだファイルを消さない）。`export_id` が空・当該 Project の書き出しでない（存在しない Project も）は 404、書き出しファイルが無ければ 409、`note` が長すぎるは 422
- `POST /projects/:id/reviews/feedback`: 成功時は、空にした取り込みフォームと、応答を取り込んだ依頼のカード 1 件（`id="review-<依頼 ID>"`。ページ上の同じカードを置き換える）だけ（201。依頼フォームは返さず、書きかけのメモを消さない）。ファイルなし・JSON として読めない・`format`/`version` が違う・判定やコメントが不正・`response_id` が `bundlepath.ValidID` を満たさない（`[A-Za-z0-9_-]{1,64}` でない、または `reviews`・Windows の予約デバイス名（`CON`・`NUL`・`COM1` など。大文字小文字を問わない）。書き出したプロジェクトバンドルを取り込めなくなるため）・ファイルが 1MB 超過（本文全体が 2 MiB 以内のとき。超えれば §0 の 413）は 422（何も保存しない）、`review_id` がこの Project のレビュー依頼でなければ 422、`response_id` が取り込み済みなら 409。取り込むと Chat Workspace のスレッドに AI の発言（表示名・判定・コメント件数）を追加する
- `PUT /projects/:id/review-comments/:commentId`: そのコメントを持つレビュー依頼の `<article>`（`id="review-<依頼 ID>"`。「未解決のコメント N 件」を含む）だけ（200）。一覧（`#review-list`）全体は返さない（依頼フォームのメモと選んだ応答ファイルを失わないため）。ボタンは `hx-target="closest article"`・`hx-sync="this:drop"`。当該 Project のコメントでなければ 404
- `POST /reviews/import`: 成功時は `HX-Redirect: /reviews/:id`（201）。ZIP として読めない・`manifest.json` と `video.mp4|webm` 以外のエントリがある・形式やバージョンが違う・動画の署名が合わない・サイズ超過（本文全体が 2 GiB + 2 MiB 以内のとき。超えれば §0 の 413）は 422（何も保存しない）、同じ `review_id` を読み込み済みなら 409
- `POST /reviews/:id/comments`・`DELETE /reviews/:id/comments/:commentId`・`PUT /reviews/:id/decision`: 変わる部分だけのフラグメント（201 / 200）。動画（`<video>`）を含む画面全体は返さない（再生位置と、他のフォームの書きかけを失わないため）。コメントの追加は、コメント一覧（`#review-comments`）と、空にした追加フォーム（`#review-comment-form`、OOB スワップ）。削除は一覧だけ（書きかけの追加フォームは残る）。判定の保存は判定の領域（`#review-decision`。保存後のバッジと応答ファイルのダウンロードリンクを含む）だけ。コメントは 1 レビュー 200 件まで（超過は 422）、`timecode` が負・秒でも 分:秒 でもない・24 時間超は 422、`decision` が不正・`reviewer_name` が空か長すぎるは 422。コメントや判定を変えると、書き出す応答の `response_id` が新しくなる
