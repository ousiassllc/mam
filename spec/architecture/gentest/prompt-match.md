# 生成テスト: 画像からプロンプトを作り、似るまでリトライする（プロンプトマッチ）

[gentest.md](gentest.md) の続き（Issue #916）。参考の画像 1 枚から、AI が英語のプロンプトを作り、モデルで生成して、参考と似ているかを測り、似ていなければ違いをもとにプロンプトを直して生成し直す。目標の似てる度に届くか、上限の回数になったら止まる。ルートは [../../api/endpoints-gentest.md](../../api/endpoints-gentest.md)、MCP は [../../api/mcp-tools-generation-test.md](../../api/mcp-tools-generation-test.md)、画面は [../../components/gentest-screen.md](../../components/gentest-screen.md)。

## 1. 流れ

1. **作る**: 参考の画像と言葉の指示（省略可。日本語でよい）を LLM（`agent/imagematch`。AgentPromptPlanner のルート。#913 の英訳と同じ「LLM の割り当て」の Prompt Planner）に見せ、**英語のプロンプト**を作らせる（`Describe`）。
2. **生成**: そのプロンプトだけで、選んだ画像モデルが生成する（直接呼び出し。代替なし）。**参考の画像はモデルに渡さない**（渡すと似て当然になり、プロンプトの出来を測れない）。
3. **測る**: 参考と生成した画像を並べて LLM（AgentVideoJudge のルート。既定は Gemini。画像を見る役割）に見せ、**似てる度（0〜100 の整数）**と、まだ違うところ（日本語。重要な順に最大 5 つ）を答えさせる（`Compare`）。
4. **直す**: 目標に届かなければ、**いちばん似ていた回**のプロンプト・その画像・違い・言葉の指示を LLM（Prompt Planner）に見せ、直したプロンプト（英語）と「直したところ」（日本語 1〜2 文）を作らせる（`Revise`）。言葉の指示があるときは、いま見ている回（最後の回）を直す。直らなかった（同じプロンプトが返った）ときは止める（同じ入力で課金しない）。
5. 3〜4 を、目標に届く・上限の回数・取り消し・失敗のどれかまで繰り返す。

### 似てる度の測り方（選んだ理由）

LLM が両方の画像を見て点を付ける。画像埋め込みの近さは「同じ被写体・似た色」までしか言えず、直すための手がかりにならない。顔の一致度（`facesim`。#910）は顔があるときだけで、風景・物・構図には使えない。LLM の比較は「何が違うか」を言葉で返せるので、そのまま次の直しの入力になる。入力は 1024 px 以下に縮める（`imagematch.Prepare`。ベンダーの上限に収める）。点は 0〜100 の整数で、範囲外・欠けた答えは `llm.ErrInvalidOutput` として止める（黙って既定値にしない）。

## 2. 進め方（`mode`）

| `mode` | 動き | 今回の回数 |
|--------|------|-----------|
| `auto`（既定。画面は「おまかせ」） | 目標（`target_score`、既定 80）に届くか `max_rounds`（1〜10、既定 5）回になるまで、自動で直して生成し直す | 最大 `max_rounds` |
| `once`（1回だけ） | プロンプトを作って 1 回だけ生成し、測って終わる。直さない | 1 |
| `adjust`（調整） | 1 回ずつ。結果を見て、言葉の指示を足して続ける | 1 |

終わったマッチは **続けられる**（`continue_batch_id`）。参考の画像・モデル・縦横比・目標は元のまま、回の番号は通しで数え、`mode`（`adjust` なら 1 回、`auto` なら `max_rounds` 回）と `instruction` を付けられる。続きも見積り → 確認 → 実行を通る。**実行中のマッチには、言葉の指示を足せる**（`Instruct`）: 次にプロンプトを直すときに取り込まれる（終わったマッチは `conflict`）。

## 3. 見積り・確認・上限

`Estimate` は、生成テストの見積りと同じく、見積りの ID（リクエストと内訳と合計の SHA-256）と合計を返す。内訳は 2 行: **モデルの行**（最大の回数 × 単価。ローカルは `free`・0 USD、単価が分からないクラウドは `unknown` で合計に入れず警告 `no_price`）と、**LLM の行**（`model` は `match_llm`。LLM の呼び出しは Take でもコスト台帳でもなく、料金表を持たないので、#913 の英訳の行と同じく単価なしで合計に入れず警告 `no_price`）。リクエストの `max_cost_usd`（この実行で使ってよい費用。省略か 0 なら設定の上限だけ）を合計が超えるときも `over_limit` が付く（メッセージは「指定した上限の費用」）。`Run` は見積りをやり直し、ID か合計が違えば `*gterr.ConflictError`、**合計が上限（`gentest.max_cost_usd`、または指定した `max_cost_usd`）を超えるなら `*gterr.ConflictError`（始めない。LLM も呼ばず、何も生成しない）**。回数が `gentest.max_items` を超える設定は `*gterr.InvalidError`。目標に届いて早く止まれば、使わなかった回の分は課金されない（見積りは最大）。

## 4. 保存（マイグレーションなし）

マッチは生成テストの **バッチ** で、各回は **その結果（`gentest_result`）**。だから画像・コスト・取り消し・履歴・お気に入り・取り込みは既存のものがそのまま使える。

- バッチの `params` に `"match": {"target_score": N}`（マッチの目印）と `aspect_ratio`。参考の画像は入力（`gentest_input`、役割 `reference`）で、履歴の詳細に出る。
- 回は **開始時に `queued` の結果として計画**する（`max_rounds` 個。プロンプトは空）。ジョブ（種別 `gentest`。`gentest.Deps.Extra` = `match.Service` が `params.match` のあるバッチを引き取る）が 1 回ずつ、プロンプトを書いて（`SetResultPrompt`。`prompt` と `sent_prompt` に入れ、プロンプト履歴にも入る）生成する。計画した結果が `queued` で残るので、進捗・取り消し・「終わったか」の判定（`queued`/`running` が無い）は通常のバッチのまま動く。**終わったとき、使わなかった `queued` の回は消す**（`DeleteQueued`）。取り消し（`Cancel`）は `queued` の回を取り消し、ジョブは次の回を始めない（作っている途中の絵は終わるのを待つ）。
- 各回の結果の `params.match`（`service/gentest/matchinfo`）: `round`（通し番号）・`target`・`score`・`differences[]`・`based_on`（直した元の回）・`base_prompt`（直す前のプロンプト）・`change`（直したところ）・`instruction`（その回に取り込んだ言葉の指示）・`error`（測れなかった理由）。
- 続き（`ContinueBatch`）は終わったバッチを開き直し、新しい `queued` の回を足し、`estimated_cost` に今回の見積りを足す（`finished_at IS NOT NULL` のものだけ。同時の続きは 2 つ目が `conflict`）。

## 5. 失敗・中断

- LLM の失敗（API キー未登録・サーキットブレーカー・タイムアウト・使えない答え・直らない）は、その回を止めてマッチを終え、理由を日本語で残す（API キー・ブレーカー・タイムアウトは設定の案内つき）。**プロンプトを書けなかった回は何も生成しない**（課金しない）。
- 生成が失敗した回は `failed`（理由は通常の結果と同じ）で、マッチは止まる。測れなかった回は、画像（課金済み）は残して `params.match.error` に理由を書き、止まる。
- mam が止まったとき、`queued`/`running` の回は失敗にする（`OnStartup`。再開しない）。成功した回は残る。

## 6. 状態（`View`）

`match.Service.View`: 回ごとの結果 ID・状態・英語のプロンプト・似てる度・違い・直したところ・指示・直す前のプロンプト、`best_round`/`best_score`/`best_prompt`（いちばん似ていた回。同点は後の回）、`stop`（`reached` 目標に届いた / `limit` 回数を使い切った / `cancelled` / `error`）、`finished`（ジョブが終わって `finished_at` が入った。最後の測定が終わるまでは false）。

## 7. テスト

`servicetest` ではなく `match` の外部テスト（`gentesttest` の偽のバックエンドと、台本どおりに答える偽の LLM `FakeMatchLLM`。時間・乱数・実 LLM に頼らない）: 見積り（最大の回数 × 単価・ローカルは無料・LLM は単価なし・上限超過・拒否）、実行の確認（なし・合計違い・リクエスト違い）、おまかせ（目標で止まる・上限で止まる・いちばん似た回から直す・使わない回を消す・参考の画像をモデルに渡さない）、1回だけ、続き（言葉の指示が履歴に残る・通し番号・見積りの加算）、実行中の指示、取り消し（次の回が始まらない）、失敗（LLM の各種・生成・測定）。`imagematch` の単体テスト（答えの検査・縮小）、`gentestrepo` の新しい操作、MCP と画面（HTMX）のテスト。
