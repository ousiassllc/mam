# 生成テスト: 画像からプロンプトを作り、似るまでリトライする（プロンプトマッチ）

[gentest.md](gentest.md) の続き（Issue #916）。参考の画像 1 枚から、AI が英語のプロンプトを作り、モデルで生成して、参考と似ているかを測り、似ていなければ違いをもとにプロンプトを直して生成し直す。目標の似てる度に届くか、上限の回数になったら止まる。ルートは [../../api/endpoints-gentest.md](../../api/endpoints-gentest.md)、MCP は [../../api/mcp-tools-generation-test.md](../../api/mcp-tools-generation-test.md)、画面は [../../components/gentest-screen.md](../../components/gentest-screen.md)。

## 1. 流れ

1. **作る**: 参考の画像と言葉の指示（省略可。日本語でよい）を LLM（`agent/imagematch`。AgentPromptPlanner のルート。#913 の英訳と同じ「LLM の割り当て」の Prompt Planner）に見せ、**英語のプロンプト**を作らせる（`Describe`）。
2. **生成**: そのプロンプトだけで、選んだ画像モデルが生成する（直接呼び出し。代替なし）。**参考の画像はモデルに渡さない**（渡すと似て当然になり、プロンプトの出来を測れない）。
3. **測る**: 参考と生成した画像を並べて LLM（AgentVideoJudge のルート。既定は Gemini。画像を見る役割）に見せ、**似てる度（0〜100 の整数）**と、まだ違うところ（日本語。重要な順に最大 5 つ）を答えさせる（`Compare`）。顔を混ぜる設定（`gentest.match_face`。下の「顔の一致度を混ぜる」）が ON のときは、顔の一致度の点を重み付きで混ぜた点が似てる度になる。
4. **直す**: 目標に届かなければ、**いちばん似ていた回**のプロンプト・その画像・違い・言葉の指示を LLM（Prompt Planner）に見せ、直したプロンプト（英語）と「直したところ」（日本語 1〜2 文）を作らせる（`Revise`）。言葉の指示があるときは、いま見ている回（最後の回）を直す。直らなかった（同じプロンプトが返った）ときは止める（同じ入力で課金しない）。
5. 3〜4 を、目標に届く・上限の回数・取り消し・失敗のどれかまで繰り返す。

### 似てる度の測り方（選んだ理由）

LLM が両方の画像を見て点を付ける。画像埋め込みの近さは「同じ被写体・似た色」までしか言えず、直すための手がかりにならない。顔の一致度（`facesim`。#910）だけでは、顔があるときしか測れず、風景・物・構図には使えない（そのため LLM の点が土台で、顔は混ぜるだけ。混ぜ方は下の「顔の一致度を混ぜる」）。LLM の比較は「何が違うか」を言葉で返せるので、そのまま次の直しの入力になる。入力は 1024 px 以下に縮める（`imagematch.Prepare`。ベンダーの上限に収める）。点は 0〜100 の整数で、範囲外・欠けた答えは `llm.ErrInvalidOutput` として止める（黙って既定値にしない）。

### 顔の一致度を混ぜる（Issue #964）

LLM の点だけだと、顔が別人でも構図と色が合えば高く出る。顔の一致度（`facesim`。#910）を混ぜると、人物の参考では顔のずれが点に出る。

- **式**: `似てる度 = round((1 − w) × LLM の点 + w × 顔の点)`（`w` = `gentest.match_face.weight`、0〜1）。顔の点は、参考の最大の顔と生成した画像の最大の顔の **SFace の埋め込みのコサイン類似度**を、`floor`（0 点）〜`ceil`（100 点）の線形に写して 0〜100 に切り詰めた値（`FaceMix.Points`）。既定は `floor` 0.2・`ceil` 0.7（OpenCV Zoo の SFace の同一人物の閾値 0.363 は約 33 点。別人は 0.2 付近までに収まる）。式・写し方・重みは `imagematch.FaceMix`（設定は `models.json` の `gentest.match_face`。`weight`・`floor`・`ceil`。書かなかった項目は既定。範囲外は設定の検査で拒否する）の 1 か所に集めた。顔の埋め込みを別のモデルに替える（#960）ときは、ここの数字を測り直す。
- **フォールバック（LLM の点だけにする）**: 参考に顔がない（風景・物・構図の参考）/ 生成した画像に顔がない / 顔のモデルか ONNX Runtime が使えない / 顔の推論か画像の読み取りに失敗、のどれか。点はそのまま LLM の点で、失敗にはしない。理由は `Scoring.Skipped`（`reference_no_face` / `generated_no_face` / `unavailable` / `error`）に残す。
- **内訳**: 顔を混ぜる設定のとき、回ごとに `Scoring`（`llm` = LLM の点、`face` = `cosine`・`points`・`weight`、顔を使えなかったときは `face_skipped`）を結果の `params.match.scoring` に残し、`View`・MCP の `get_prompt_match`・画面（回のカードの「LLM 40点 × 50% ＋ 顔 100点（一致度 1.00）× 50%」と、結果の詳細の「点の内訳」）に出す。顔を混ぜない設定のときは `Scoring` を作らない（保存済みのマッチは今までどおり）。目標に届くかの判定・ベストの回・直しの土台は、混ぜたあとの点で決める。「何が違うか」の言葉は LLM のままで、顔の点は言葉を作らない。
- **既定は OFF（`weight` 0）**: SFace の重みのライセンスは Apache-2.0（OpenCV Zoo の `models/face_recognition_sface` の README と LICENSE。YuNet は MIT）だが、ONNX の重みをどのデータで学習したかは OpenCV Zoo にも元のリポジトリ（`zhongyy/SFace`。論文の実験は CASIA-WebFace・VGGFace2・MS-Celeb-1M）にも書かれておらず、学習データの権利（商用で使ってよいか）は一次情報で確かめられない（`../model-adapters.md` §8。2026-11-02 に再確認）。確かめられるまで、保守的に混ぜない。使う人は設定で `weight` を上げる。商用可能な顔の埋め込みへの差し替え（#960）はこの Issue の範囲外。
- **設定は起動時に 1 度だけ読む**: `gentest.match_face` は mam の起動時に読まれ（`Matcher` に渡される）、`models.json` を書き換えても**再起動するまで反映されない**（`gentest.max_cost_usd` などと違い、実行のたびには読み直さない）。`weight` が 0 のときは、顔のモデルが使える状態でも顔の推論は呼ばず、点も `Scoring` も顔の設定が無いときと同じ。

## 2. 進め方（`mode`）

| `mode` | 動き | 今回の回数 |
|--------|------|-----------|
| `auto`（既定。画面は「おまかせ」） | 目標（`target_score`、既定 80）に届くか `max_rounds`（1〜10、既定 5）回になるまで、自動で直して生成し直す | 最大 `max_rounds` |
| `once`（1回だけ） | プロンプトを作って 1 回だけ生成し、測って終わる。直さない | 1 |
| `adjust`（調整） | 1 回ずつ。結果を見て、言葉の指示を足して続ける | 1 |

終わったマッチは **続けられる**（`continue_batch_id`）。参考の画像・モデル・縦横比・目標は元のまま、回の番号は通しで数え、`mode`（`adjust` なら 1 回、`auto` なら `max_rounds` 回）と `instruction` を付けられる。続きも見積り → 確認 → 実行を通る。**実行中のマッチには、言葉の指示を足せる**（`Instruct`）: 次にプロンプトを直すときに取り込まれる（終わったマッチは `conflict`）。

## 3. 見積り・確認・上限

`Estimate` は、生成テストの見積りと同じく、見積りの ID（リクエストと内訳と合計の SHA-256）と合計を返す。内訳は 3 行: **モデルの行**（最大の回数 × 単価。ローカルは `free`・0 USD、単価が分からないクラウドは `unknown` で合計に入れず警告 `no_price`）と、**LLM の 2 行**（Issue #965）。**プロンプトの作成・修正**（`model` は `match_llm`。Prompt Planner のルートの主のターゲット）と**似てる度の比較**（`match_llm_compare`。AI Video Judge のルートの主のターゲット）で、どちらも「最大の回数」回（1 回に 1 度ずつ書き（最初の回は参考から作る・以降は直す）、1 度ずつ比べる）。**単価はトークン単価**（`llm.PriceOf`。Anthropic・OpenAI・Google の公式の価格ページで確かめたモデルだけの表。確かめていないモデル ID（スナップショット・プレビューの別名を含む）と、ChatGPT のプラン（`chatgpt-subscription`・`chatgpt-codex`。1 回ごとの課金ではない）は載せない）に、1 回の呼び出しで使うトークン数の**見込み**（`imagematch.Matcher.Plan`。画像 1 枚 1600 トークン、答えは長めに取る。見積りは呼び出す前なので実測できず、安全側の仮定。**実際に呼んだ後は実測する**。下の「実測」）を掛けて出す。書く側は「直す」（画像 2 枚・プロンプト全文）と「作る」のうち高いほうで見積もる。単価が分かる行は `priced` で小計が合計に入り、**分からない行だけ** `unknown` で合計に入れず警告 `no_price`（数字は作らない）。呼び出しは代替のターゲットに切り替わることがあるが、見積りは主のターゲットで出す。LLM の呼び出しは Take でもコスト台帳（`cost_ledger_entry`）でもないので、台帳には書かない（見積りの合計と、費用の上限の判定に入る。実測の費用は回の `params.match.llm` に残す。下の「実測」）。リクエストの `max_cost_usd`（この実行で使ってよい費用。省略か 0 なら設定の上限だけ）を合計が超えるときも `over_limit` が付く（メッセージは「指定した上限の費用」）。`Run` は見積りをやり直し、ID か合計が違えば `*gterr.ConflictError`、**合計が上限（`gentest.max_cost_usd`、または指定した `max_cost_usd`）を超えるなら `*gterr.ConflictError`（始めない。LLM も呼ばず、何も生成しない）**。回数が `gentest.max_items` を超える設定は `*gterr.InvalidError`。目標に届いて早く止まれば、使わなかった回の分は課金されない（見積りは最大）。

**実測（Issue #981）**: `llm.Response.Usage`（`*llm.Usage`。入力・出力のトークン数）はプロバイダーが答えに付けた使用量で、付けない答え（`chatgpt-codex` は常に、ほかも使用量の欄が無い応答）は **nil（不明）**で、0 トークンとは区別する。`Describe`・`Compare`・`Revise` は呼び出しごとの `imagematch.Call` を返し、答えたターゲット（フォールバックしたときは代替のもの）の `provider`・`model`、`input_tokens`・`output_tokens`、`measured`（`true` = プロバイダーが報告した実測、`false` = 使用量が無かったので上の見込みのトークン数で置いた仮定）、`usd`（`llm.PriceOf` の単価 × トークン数。単価が分からないモデル・ChatGPT のプランは**省く**）を持つ。回の結果の `params.match.llm[]`（`matchinfo.Round.LLM`。書く / 直す、比べるの順。答えが使えず捨てた呼び出しは入らない）に残り、`View.Rounds[].LLM` と、実測の合計 `View.LLMUSD`（単価の分かる呼び出しの合計。`View.LLMAssumed` は仮定のトークン数が混ざっていること）に出る（MCP の `get_prompt_match` も同じ）。トークンの数え方: Anthropic は `input_tokens` にキャッシュの作成・読み取りを足す（mam は `cache_control` を付けないので 0）、OpenAI は `prompt_tokens` / `completion_tokens`（推論トークンは出力に含まれる）、Google は `promptTokenCount` と `candidatesTokenCount` + `thoughtsTokenCount`（考えるトークンも出力として課金される）、ChatGPT のプラン（`chatgpt-subscription`）は `response.completed` の `usage`。見積りの費用そのものは今までどおり見込みで出し、実測は履歴に残すだけ（次の見積りに過去の実測は使わない: モデルも画像の大きさも回ごとに違うので、安全側の仮定のほうが予算の確認として確かである）。 **答えが使えない形だった呼び出しも課金されている**: JSON として読めない・点が 0〜100 の外・プロンプトが空・直したプロンプトが元のまま（`ErrNotRevised`）のときも、`Describe`・`Compare`・`Revise` は答えを得ていれば `Call` をエラーと一緒に返し（答えが無い呼び出し＝タイムアウト・API キー無し・接続失敗は零値の `Call`。`Call.Made()` が false）、回はその `Call` を `params.match.llm[]` に残してから失敗する（`View.LLMUSD` の合計に入る。Issue #994）。

**最初の見積りの待ち時間（Issue #981）**: 見積りは LLM も画像モデルも呼ばない（参考画像の保存・モデルの選択・単価の計算だけ）。コードから見つかった待ちの候補は、モデル 1 つを引く `Catalog.Model` が、全モデルの一覧を作ってから 1 つを選んでいたこと。一覧のモデルごとに、API キーの有無を OS の資格情報ストアへ問い合わせ（`Configured`。応答しないときは 1 回 5 秒の制限まで待つ）、年齢ゲートの判定（`Hidden`。ワークフローのグラフを読む）を走らせるので、キーのストアが遅い環境ではモデル数 × 待ちになりうる。今は引いたモデル 1 つだけを調べる（テストで固定）。**約 20 秒の原因がこれだったかは実環境（OS のキーストアの応答時間・ComfyUI のワークフローの数）でしか確かめられず、未確認**。

## 4. 保存（マイグレーションなし）

マッチは生成テストの **バッチ** で、各回は **その結果（`gentest_result`）**。だから画像・コスト・取り消し・履歴・お気に入り・取り込みは既存のものがそのまま使える。

- バッチの `params` に `"match": {"target_score": N}`（マッチの目印）と `aspect_ratio`。参考の画像は入力（`gentest_input`、役割 `reference`）で、履歴の詳細に出る。
- 回は **開始時に `queued` の結果として計画**する（`max_rounds` 個。プロンプトは空）。ジョブ（種別 `gentest`。`gentest.Deps.Extra` = `match.Service` が `params.match` のあるバッチを引き取る）が 1 回ずつ、プロンプトを書いて（`SetResultPrompt`。`prompt` と `sent_prompt` に入れ、プロンプト履歴にも入る）生成する。計画した結果が `queued` で残るので、進捗・取り消し・「終わったか」の判定（`queued`/`running` が無い）は通常のバッチのまま動く。**終わったとき、使わなかった `queued` の回は消す**（`DeleteQueued`）。取り消し（`Cancel`）は `queued` の回を取り消し、ジョブは次の回を始めない（作っている途中の絵は終わるのを待つ）。
- 各回の結果の `params.match`（`service/gentest/matchinfo`）: `round`（通し番号）・`target`・`score`・`differences[]`・`based_on`（直した元の回）・`base_prompt`（直す前のプロンプト）・`change`（直したところ）・`instruction`（その回に取り込んだ言葉の指示）・`error`（測れなかった理由）・`llm[]`（その回の LLM 呼び出しのトークン数・実測か仮定か・費用。§3「実測」）。
- 続き（`ContinueBatch`）は終わったバッチを開き直し、新しい `queued` の回を足し、`estimated_cost` に今回の見積りを足す（`finished_at IS NOT NULL` のものだけ。同時の続きは 2 つ目が `conflict`）。

## 5. 失敗・中断

- LLM の失敗（API キー未登録・サーキットブレーカー・タイムアウト・使えない答え・直らない）は、その回を止めてマッチを終え、理由を日本語で残す（API キー・ブレーカー・タイムアウトは設定の案内つき）。**プロンプトを書けなかった回は何も生成しない**（課金しない）。
- 生成が失敗した回は `failed`（理由は通常の結果と同じ）で、マッチは止まる。測れなかった回は、画像（課金済み）は残して `params.match.error` に理由を書き、止まる。
- mam が止まったとき、`queued`/`running` の回は失敗にする（`OnStartup`。再開しない）。成功した回は残る。

## 6. 状態（`View`）

`match.Service.View`: 回ごとの結果 ID・状態・英語のプロンプト・似てる度・点の内訳（`scoring`。顔を混ぜているときだけ）・違い・直したところ・指示・直す前のプロンプト、`best_round`/`best_score`/`best_prompt`（いちばん似ていた回。同点は後の回）、`stop`（`reached` 目標に届いた / `limit` 回数を使い切った / `cancelled` / `error`）、`finished`（ジョブが終わって `finished_at` が入った。最後の測定が終わるまでは false）。

## 7. テスト

`servicetest` ではなく `match` の外部テスト（`gentesttest` の偽のバックエンドと、台本どおりに答える偽の LLM `FakeMatchLLM`。時間・乱数・実 LLM に頼らない）: 見積り（最大の回数 × 単価・ローカルは無料・LLM のトークン単価が合計に入り `no_price` が出ないこと・単価の分からない行だけ警告・LLM の費用が上限の判定に入ること・上限超過・拒否）、顔を混ぜる（式と境界は `imagematch` の外部テスト: 重みの端・コサインの写し方と切り詰め・参考に顔なし / 生成に顔なし / エンジンの失敗 / モデルなしでの LLM の点へのフォールバックと理由・OFF なら顔のエンジンに触れない。目標の判定が混ぜた点で決まり、内訳が回に残ること）、実行の確認（なし・合計違い・リクエスト違い）、おまかせ（目標で止まる・上限で止まる・いちばん似た回から直す・使わない回を消す・参考の画像をモデルに渡さない）、1回だけ、続き（言葉の指示が履歴に残る・通し番号・見積りの加算）、実行中の指示、取り消し（次の回が始まらない）、失敗（LLM の各種・生成・測定）。`imagematch` の単体テスト（答えの検査・縮小）、`gentestrepo` の新しい操作、MCP と画面（HTMX）のテスト。
